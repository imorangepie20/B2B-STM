# 모바일 사이드바 폭 수정

## 근본 원인

공용 `SheetContent`의 방향별 기본 폭 `data-[side=left]:w-3/4`가 사이드바의 `w-(--sidebar-width)`보다 CSS 선택자 우선순위가 높았습니다. 그 결과 390px 뷰포트에서 사이드바가 정확히 75%인 약 292.5px를 차지했습니다. `rem` 값을 줄여도 이 규칙이 계속 우선하므로 문제를 해결하지 못했습니다.

## 변경 내용

- `SheetContent`에 `useDefaultWidth` 옵션을 추가했습니다. 기본값은 `true`라 다른 시트의 기존 폭은 유지됩니다.
- 모바일 사이드바는 `useDefaultWidth={false}`로 공용 `w-3/4` 규칙을 제외합니다.
- 사이드바 폭은 CSS 변수 기반 `256px`로 정하고 작은 화면에서는 `calc(100vw - 3rem)`을 넘지 않게 했습니다.
- 모바일 시트의 닫기 버튼을 표시해 메뉴를 명시적으로 닫을 수 있게 했습니다.
- 관리자·창고·거래처 모바일 메뉴는 항목을 선택하면 즉시 닫힙니다.
- 폭을 인라인 스타일로 덮어쓰지 않고 충돌하는 기본 규칙을 컴포넌트 수준에서 제거했습니다.

## 검증

- Playwright에서 모바일 사이드바의 계산 폭이 256px인지 확인합니다.
- 닫기 버튼 노출과 클릭 후 시트가 닫히는 동작을 확인합니다.
- 현재 메뉴를 다시 선택하는 경우에도 시트가 닫히는 동작을 확인합니다.
- 전체 16개 화면의 데스크톱·모바일 시각 회귀 검사 32/32를 통과했습니다.
