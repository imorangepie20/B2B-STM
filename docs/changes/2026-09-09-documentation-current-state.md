# 기준 문서 현행화

## 문제

초기 기획·구현 계획의 체크박스와 개요 문서가 기능 완료 후 갱신되지 않아 현재 구현과 상반된 설명이 남아 있었습니다. 제품 workspace·업무 테이블·MFA·실제 화면이 이미 존재하지만 일부 문서는 여전히 미구현 또는 검토용으로 표시했습니다.

## 변경

- `current-development-context.md`를 현재 실행 환경, 완료 범위, 최신 검증, 남은 작업 중심의 인계 문서로 재작성했습니다.
- 제품 구현 계획은 `[x]` 완료, `[~]` 부분 완료, `[ ]` 미구현을 구분하는 현행 체크리스트로 교체했습니다.
- 로드맵과 기획 점검표에 완료된 1~7단계와 현장 물류·문서 연동·배포 검수의 후속 단계를 반영했습니다.
- 개발 환경과 인증 문서를 현재 패키지 버전, DB 역할, MFA·이메일·계정 화면 구현 상태로 갱신했습니다.
- 시스템·transaction·DB·화면 설계 문서에서 실제 구현과 목표 설계를 구분했습니다.
- 주문·반품·정산 정책에 현재 구현된 동작과 피킹·실사·환불 등 남은 범위를 표시했습니다.
- 완료된 과거 상세 계획에는 완료 또는 부분 완료 상태와 현재 기준 문서 링크를 추가했습니다.
- 날짜별 `docs/changes/` 기록의 당시 테스트 수치는 변경하지 않았습니다.

## 현재 우선순위

다음 구현은 피킹 수량·검수 완료 상태와 검수 수량 이내 출고 제약입니다. 목표 규모 30분 성능 본 시험은 사용자 요청으로 중단 상태를 유지합니다.

## 검증

- 기준 문서의 오래된 `제품 폴더 미생성`, `업무 테이블 미구현`, `MFA 미구현`, `구현 전 화면 제안` 표현을 검색해 제거하거나 역사적 문맥으로 명시했습니다.
- Markdown 상대 링크와 공개 저장소 포함 경로를 검사합니다.
- `npm.cmd run repo:verify-public`: 제외 규칙 7개, 공개 후보 380개 경로 통과
