# 관리자 재고·반품 목록 서버 검색·페이지 처리

## 변경 이유

재고 정정과 반품 차감 화면이 전체 목록을 한 번에 내려받았습니다. 상품·창고·반품 건수가 증가하면 응답과 렌더링 비용이 계속 커지고, 긴 선택 목록에서 작업 대상을 찾기 어려워집니다.

## 변경 내용

- `GET /api/admin/inventory`에 창고·SKU·상품명 검색과 50건 단위 페이지 응답을 추가했습니다.
- `GET /api/admin/returns/credits/pending`에 거래처·SKU·상품명·불량 사유 검색과 페이지 응답을 추가했습니다.
- 두 관리자 화면은 300ms 검색 지연, 전체 결과 건수, 이전·다음 이동을 사용합니다.
- 처리 후 현재 페이지가 없어지면 유효한 마지막 페이지를 다시 조회합니다.
- 대시보드와 기존 자동화가 사용하는 매개변수 없는 배열 응답은 유지합니다.

## 검증

- 새 페이지 응답이 구현 전 실패하는 것을 확인한 뒤 실제 PostgreSQL 시나리오로 검색 결과와 대상 ID를 검증했습니다.
- `order-pagination.test.mjs`, `order-reservation.test.mjs` 총 20건이 통과했습니다.
- `npm.cmd run build:api`, `npm.cmd run build:web`가 통과했습니다.

## 남은 작업

- 운영 인수 문서와 포트폴리오 증빙 정리를 이어갑니다.
