# 불량품 해결과 실제 환불

## 변경 이유

기존 반품 처리는 불량 수량을 격리하거나 폐기하는 최초 판정까지만 기록했습니다. 격리 이후 공급처 반환·폐기 결과와 실제 송금한 환불을 추적할 저장 구조가 없어 운영 흐름이 끝나지 않았습니다.

## 구현 내용

- 불량품을 즉시 폐기하거나 공급처 반환으로 판정할 수 있습니다.
- 격리 건은 최초 격리 기록을 유지한 채 공급처 반환 또는 폐기 해결 이력을 별도로 기록합니다.
- 공급처 반환에는 공급처, 반송·접수 참조번호, 수량, 사유를 기록합니다.
- 실제 환불은 미배분 입금 또는 반품 차감액을 원천으로 삼고 원천 금액을 초과할 수 없습니다.
- 환불된 입금은 다시 배분하거나 취소할 수 없으며, 반품 차감액 환불은 매출 원장의 양수 조정으로 기록합니다.
- 관리자 `/admin/refunds`에서 원천별 환불 가능액, 환불 등록, 통계와 이력을 제공합니다.
- 반품 처리 화면에서 격리 건을 해결하고 거래처 정산 화면에서 실제 환불 내역을 확인할 수 있습니다.
- 불량 판정·해결과 환불은 감사 로그에서 검색할 수 있습니다.

## 동시성과 중복 방지

불량품 해결은 격리 행을 잠그고 누적 해결 수량을 확인합니다. 환불은 원천 입금 또는 반품 차감 행을 잠근 뒤 기존 환불·배분 합계를 다시 계산합니다. 모든 명령은 `requestId`로 재시도 시 같은 결과를 반환하며 환불 참조번호의 전역 중복도 차단합니다.

## 검증

- 공급처 반환 동시 재시도와 격리 수량 초과 방지를 PostgreSQL 통합 테스트로 확인했습니다.
- 반품 차감액 환불의 매출 원장 조정, 미배분 입금 환불, 환불된 입금의 취소 차단을 확인했습니다.
- foundation 68/68, 프로덕션 빌드, 관리자·창고·거래처 16개 화면의 데스크톱·모바일 32/32, DB 역할 검사 33개 테이블·14개 무결성 검사를 통과했습니다.
