# 운영 인수 권한·성능 스모크 자동화

작성일: 2026-09-07

## 변경 이유

주요 업무 흐름과 초기 데이터 이관은 구현됐지만, 운영 인수 기준에 있는 역할 우회 방지와 30명 동시 조회 목표를 한 명령으로 재검증할 수 없었습니다. 화면과 API가 정상인 상태에서도 이후 변경으로 권한 또는 조회 성능이 퇴행할 수 있어 반복 가능한 점검이 필요했습니다.

## 변경 내용

- `scripts/lib/performance-metrics.mjs`에 nearest-rank percentile, 측정 요약, 성능 기준 판정을 구현했습니다.
- `scripts/verify-operational-acceptance.mjs`가 데모 계정용 임시 세션을 만들고 9개 권한 행렬을 실제 HTTP 상태 코드로 검증합니다.
- 30개 동시 작업자로 관리자·창고·거래처의 대표 조회 endpoint 11개를 총 300회 호출합니다.
- 전체와 endpoint별 요청 수, p50, p95, 최대 응답 시간, 예상하지 못한 오류 수·비율을 JSON으로 출력합니다.
- `npm.cmd run ops:acceptance-smoke` 명령과 운영 안내 문서를 추가했습니다.

## 검증 결과

- 권한 행렬 9개가 모두 기대한 `200`, `401`, `403`으로 응답했습니다.
- 300개 요청에서 예기치 않은 오류는 0건이었습니다.
- 최종 재실행에서 전체 p50은 85.7ms, p95는 107.9ms, 최대 응답 시간은 138.4ms였습니다.
- 가장 높은 endpoint p95는 `/api/admin/settlements`의 117.2ms였습니다.
- 읽기 API p95 1,000ms와 오류율 0.1% 기준을 통과했습니다.
- 점검 종료 후 자신이 만든 임시 세션을 모두 삭제했는지 `DELETE ... RETURNING` 결과로 확인합니다.
- 전체 foundation 45건과 DB 22개 table·7개 업무 무결성 검사가 통과했습니다.

## 한계와 다음 검증

측정값은 현재 로컬 개발 장비와 데모 데이터 규모의 스모크 결과입니다. 주문 100,000건, 주문행 1,000,000건과 30분 지속 부하는 아직 실행하지 않았으므로 운영 규모 성능 달성으로 간주하지 않습니다. 다음 단계에서 목표 규모 fixture, 조회 70%·변경 30% workload, 동시 주문·중복 요청 무결성 측정을 별도 본 시험으로 구성합니다.

주문 목록 서버 페이지 처리 후 브라우저 검증과 동시에 다시 실행한 결과도 오류 0건, 전체 p95 176.6ms로 기준을 통과했습니다.
