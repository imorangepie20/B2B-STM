# 채용 담당자용 GitHub 프로젝트 소개 개편

작성일: 2026-09-13.

## 변경 이유와 승인

사용자가 이 프로젝트를 GitHub 메인 포트폴리오 소개용으로 사용하며 대상은 채용 담당자라고 지정했습니다. 핵심 문제 해결·설계·검증 증거를 먼저 소개하고 상세 실행 절차를 아래로 이동하는 README 개편안을 승인했습니다.

기존 README는 배포 실행서와 업무 기능 설명으로 시작해 설계 역량과 검증 증거를 빠르게 훑기 어려웠습니다. 공개 소개의 목적만 변경하며 제품 동작과 업무 정책은 변경하지 않습니다.

## 변경 내용

- 루트 README에 배포 사이트, 설계·검증·데모 동선 링크를 배치했습니다.
- 동시 재고 예약, 멱등 요청과 응답 유실 복구, 원자적 출고, 마감 후 반품 조정, 서버 권한 경계를 문제·해결·증거로 연결했습니다.
- 업무 API와 DB의 책임, 단일 transaction 선택, 원장 보존, outbox 분리의 설계 판단을 설명했습니다.
- 긴 대표 캡처와 역할별 화면은 GitHub `details`로 접어 첫 화면에서 핵심 내용을 읽을 수 있게 했습니다. 기존 공개 DEMO 캡처를 재사용했습니다.
- 대화형 아키텍처 HTML은 GitHub에서 실행되지 않으므로 이미지 링크와 로컬 열기 안내를 추가했습니다.
- foundation 79/79는 2026-09-10 배포 기록을 사용하고 모든 기능 검증 수치는 이전 실행 이력임을 명시했습니다.
- 실사용 매출·개인 기여율·팀 규모·개발 기간은 추정하지 않았습니다. 로컬 성능과 실제 배포 검수의 한계를 유지했습니다.
- 포트폴리오 자료 인덱스와 현재 개발 인계에 채용 소개 진입점을 연결했습니다. 위시켓 자료는 별도 용도로 보존했습니다.

## 검증 결과

- 열어둔 Chrome `https://stm.approid.team/admin`에서 인증된 관리자 대시보드의 지표·차트·DEMO SKU 표시와 기존 캡처의 화면 구성을 읽기 전용으로 확인했습니다. 업무 명령은 실행하지 않았습니다.
- 변경 문서 4개의 로컬 링크 70개와 삽입 이미지 6개가 존재하며 Git 공개 후보에 포함됨을 확인했습니다. 문서 내 중복 참조를 포함한 수치입니다.
- README의 npm 명령 참조 15개를 루트 또는 Web workspace의 `package.json`과 대조했습니다. code fence와 `details` 태그의 짝도 확인했습니다.
- `npm.cmd run repo:verify-public`: 제외 규칙 7개, 공개 후보 456개 경로 검사 통과. 이 검사는 설정된 텍스트·비밀값 유출 규칙의 검사이며 이미지 전체에 대한 개인정보 자동 판독은 아닙니다.
- `git diff --check`: 공백 오류 없음. Windows Git의 LF → CRLF 안내만 출력됐습니다.

## 미검증·변경 제외

- 이번 작업에서 기능 통합 테스트·E2E·빌드·성능 시험을 재실행하지 않습니다. 제품 코드는 변경하지 않았습니다.
- 현재 브라우저의 대시보드 확인은 전체 역할·반응형 동작·배포 장애 복구 검증이 아닙니다.
- 문서 검증 시점에는 GitHub 웹의 변경된 README 렌더링을 확인하지 않았습니다. 이후 사용자의 별도 요청으로 이 문서 변경 4개를 `main`에 commit·push하며, 프로필 저장소는 변경하지 않습니다.
- `customer -> order -> reservation -> shipment -> settlement -> payment`, `receipt -> inventory`, `return -> inventory/settlement`와 후속 피킹·검수·실사·환불 관계의 구현은 변경하지 않았습니다.
