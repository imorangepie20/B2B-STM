# MFA API 구현

등록·확인·추가 인증·복구 API를 추가했습니다. 모든 요청은 세션·Origin·CSRF 검사를 거칩니다.

| POST endpoint | 동작 |
|---|---|
| /api/auth/mfa/enroll | password 재확인 후 secret·uri 반환, 등록 유효기간 10분 |
| /api/auth/mfa/confirm | 같은 세션의 code 확인 후 활성화·복구 코드 10개 반환 |
| /api/auth/mfa/verify | 인증 앱 code 확인 후 현재 세션의 MFA 확인 |
| /api/auth/mfa/recover | 복구 code를 일회 소비하고 현재 세션의 MFA 확인 |

[otplib 공식 라이브러리](https://github.com/yeojz/otplib) 13.5.0의 TOTP를 사용합니다. 6자리·30초 간격·±30초 허용이며 성공한 timeStep을 저장해 재사용을 막습니다. Node crypto의 AES-256-GCM으로 비밀키를 암호화하며 사용자 ID를 AAD로 연결합니다. 복구 코드는 16바이트 난수 10개이며 DB에는 해시만 저장합니다.

MFA_ENCRYPTION_KEY는 지속 보관할 32바이트 난수의 hex 64자입니다. 미설정 시 MFA API는 503을 반환합니다. 실제 개발 키는 이번에 생성하지 않았고 테스트 키만 메모리에서 사용했습니다. 키는 DB와 별도 백업이 필요하며 임의 변경하면 기존 MFA 복호화가 실패합니다.

사용자 행·세션을 잠그고 계정·거래처·세션 상태를 재검사합니다. 계정 기준 실패 5회 후 15분 차단하며 실패 기록도 커밋합니다. 등록/확인/인증/복구/실패 이벤트를 저장합니다. 등록 미확인 상태는 권한 상승을 허용하지 않으며 이미 등록된 계정은 재등록을 거절합니다.

0007 migration을 개발·테스트 DB에 적용했고 개발 재실행 0건을 확인했습니다. API 빌드와 전체 foundation 테스트 16개가 통과했습니다. 실제 DB·HTTP에서 암호화 저장, 등록 세션 불일치, 정상 인증, TOTP 재사용 차단, 복구 동시 소비 1회, 실패 제한을 확인했습니다.

초기 관리자 생성·개발 암호화 키 준비·계정 UI·실제 휴대폰 인증 앱 검증은 다음 작업입니다. 기기 교체·복구 코드 재발급·키 회전 도구·감사 보존 정책은 미구현입니다. 복구 코드는 로그인 세션의 추가 인증용이며 비밀번호 재설정이나 MFA 기기 변경을 수행하지 않습니다. MFA 확인 시 기존 세션 토큰을 유지하며 토큰 회전은 후속 보완입니다. Cloudflare 화면 사본에는 연결하지 않았습니다.
