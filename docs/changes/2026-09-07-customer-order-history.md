# 거래처 주문 진행 이력과 역할별 수량 일치 검증

## 변경 이유

기존 거래처 포털은 새 주문 접수만 제공해 접수 후 재고 확보와 부분 출고 진행을 확인할 수 없었습니다. 관리자와 창고 화면에는 같은 주문이 보였지만 세 역할이 동일한 수량을 표시하는지 브라우저 업무 흐름에서 함께 검증하지 않았습니다.

## 변경 내용

### 거래처 주문 조회 API

- `GET /api/orders`는 로그인한 거래처 자신의 주문만 최근 순으로 반환합니다.
- 주문별 창고, 접수·확정 시각과 품목의 `requestedQuantity`, `shippedQuantity`, `remainingReservedQuantity`, `waitingQuantity`, `cancelledQuantity`를 제공합니다.
- `unitPrice`는 금액 정밀도를 잃지 않도록 문자열로 반환합니다.
- 활성 예약만 현재 예약 잔량으로 계산하고, 취소 주문은 미출고 잔량을 취소 수량으로 분리합니다.
- `customer_id` 조건을 조회 자체에 적용해 다른 거래처 주문이 응답에 포함되지 않게 했습니다.

### 거래처 주문 이력 화면

- `/portal/orders/history`에 진행 주문, 미확보 수량, 누적 출고 요약과 검색·상태 필터를 추가했습니다.
- 접수, 일부 확보, 출고 대기, 부분 출고, 출고 완료, 취소, 거절 상태를 실제 수량으로 계산합니다.
- 주문 상세에서 주문·누적 출고·출고 예약·미확보·취소 수량과 주문 당시 단가·총액을 함께 표시합니다.
- 새 주문 접수가 성공하면 주문 이력 화면으로 이동해 후속 상태를 바로 확인합니다.
- 데스크톱은 주문 목록과 7열 품목표를 함께 표시합니다. 모바일은 표를 상품 카드로 바꿔 단가와 다섯 가지 수량을 잘림 없이 표시합니다.
- 상단 메뉴와 모바일 사이드바는 가장 긴 일치 경로를 활성화해 `상품 주문`과 `주문 내역`이 동시에 선택되지 않게 했습니다.

### 브라우저 업무 흐름 안정화

- 부분 출고 3개 후 창고의 출고 후 잔량 2개, 관리자의 누적 출고 3개·출고 예약 2개, 거래처의 누적 출고 3개·출고 예약 2개가 같은 브라우저 흐름에서 일치하는지 검증합니다.
- 주문 접수 직후 화면 이동과 겹친 과거 응답 본문 읽기를 제거하고, 저장된 주문 ID를 DB에서 조회해 후속 화면을 선택합니다.
- 테스트는 자신이 만든 창고와 주문을 ID로 선택해 기존 개발 데이터나 다른 테스트 데이터 정렬에 의존하지 않습니다.
- 세션 수준 advisory lock으로 브라우저 E2E를 직렬화하고, 강제 종료가 남긴 `Browser E2E` 전용 fixture를 다음 실행에서 정리합니다.
- 실패 시 브라우저 컨텍스트를 먼저 닫고 DB fixture를 제거해 정리 쿼리가 대기하지 않도록 했습니다.

## 검증 결과

- `npm.cmd run build:api`: 통과
- `npm.cmd run build:web`: 통과, 18개 route 생성
- `npm.cmd run db:verify`: 통과
- `npm.cmd run test:foundation`: 28건 통과
- `npm.cmd run test:e2e --workspace=@b2b-stm/web`: 로그인, 주문 접수, 확정, 부분 출고와 역할별 수량 일치, 반품, 정산, 입금 배분, 로그아웃까지 통과
- Playwright 1440px: 문서 폭 1440px, 가로 넘침 없음
- Playwright 390px: 문서 폭 390px, 가로 넘침 없음. 모바일 상품 카드에서 모든 수량 확인
