# 창고 대기 업무 서버 검색·페이지 처리

## 변경 이유

출고 대기와 반품 검수 화면이 대기 자료 전체를 한 번에 내려받고 브라우저에서 검색했습니다. 대기 건수가 늘면 모바일 화면의 최초 응답과 렌더링 비용이 계속 증가하고, 현재 내려받은 자료만으로 업무 건수를 해석하게 됩니다.

## 변경 내용

- `GET /api/warehouse/shipments/queue`에 주문 단위 페이지 처리와 주문번호·거래처·창고·SKU·상품명 검색을 추가했습니다.
- 한 주문의 출고 품목이 서로 다른 페이지로 분리되지 않도록 주문 ID를 먼저 페이지 처리한 뒤 해당 주문의 활성 예약 품목을 조회합니다.
- `GET /api/warehouse/returns/queue`에 반품 행 단위 페이지 처리와 반품번호·거래처·창고·SKU·상품명·사유 검색을 추가했습니다.
- 두 창고 화면은 300ms 검색 지연, 전체 건수, 이전·다음 이동을 사용합니다.
- 기존 자동화와 이전 클라이언트가 매개변수 없이 호출하는 배열 응답은 유지합니다.

## 검증

- `order-pagination.test.mjs`와 실제 PostgreSQL을 사용하는 `order-reservation.test.mjs` 총 20건이 통과했습니다.
- `npm.cmd run build:api`, `npm.cmd run build:web`가 통과했습니다.
