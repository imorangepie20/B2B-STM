# 배송·반품 첨부 증빙

작성일: 2026-09-09.

## 변경 이유

배송 인수와 반품 파손 상태는 메모만으로 확인하기 어려워 사진·문서 원본을 업무 건에 연결해야 합니다. 공개 정적 경로에 파일을 두거나 URL만 숨기는 방식은 거래처 격리를 보장하지 않으므로, 매 목록·다운로드에서 업무 대상과 현재 사용자의 권한을 다시 확인하도록 구현했습니다.

## 구현 내용

- 배송 출고 건과 반품 요청 건에 JPEG·PNG·PDF를 최대 10MB, 업무 건당 최대 5개 첨부합니다.
- 파일은 공개 경로가 아닌 PostgreSQL `bytea`에 저장하며 파일명, 콘텐츠 유형, 크기, SHA-256, 작업자와 시각을 함께 보존합니다.
- 확장자, 요청 콘텐츠 유형과 JPEG·PNG·PDF magic signature가 일치해야 저장합니다.
- 창고 담당자는 배송·반품 증빙을 조회하고 배송 증빙을 추가할 수 있습니다. 거래처 사용자는 자기 거래처 반품에만 첨부할 수 있고, 자기 거래처의 배송·반품 증빙만 다운로드할 수 있습니다.
- 같은 파일의 중복 첨부와 5개 초과를 transaction advisory lock과 DB unique 제약으로 차단합니다.
- 응답에는 `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`와 안전한 다운로드 파일명을 적용합니다.
- 배송 관리, 거래처 반품 요청, 창고 반품 검수 화면에 업로드·조회·다운로드 UI를 연결했습니다.
- 데모 배송과 반품에 실제 1×1 PNG 증빙을 넣어 브라우저에서 즉시 확인할 수 있습니다.

## 검증 결과

- 개발·테스트 DB에 `0037_business_attachments.sql` 적용
- 위조 PNG 거절, 창고 업로드, 고객의 배송 업로드 차단, 고객 소유 배송 증빙 조회·원문 다운로드 통합 테스트 통과
- API와 Web production build 통과
- `npm.cmd run test:foundation`: 71/71 통과
- `npm.cmd run ops:verify`: 35개 테이블과 15개 무결성 검사 통과

허용 형식의 magic signature와 메타데이터 일치 검증에 더해 ClamAV 저장 전 검사를 후속 구현했습니다. 운영 계약과 검증 범위는 [첨부 악성 파일 검사 연동](2026-09-09-attachment-malware-scanning.md)을 따릅니다.
