# 역할별 업무 통계 그래프 확장

## 변경 이유

원형 비율 그래프만으로는 주문 증가, 출고 지연, 재고 위험, 반품 판정, 미수금 회수처럼 시간과 우선순위가 중요한 업무를 판단하기 어려웠습니다. 각 화면에서 실제로 내려야 하는 결정에 맞춰 그래프 종류와 집계 범위를 다시 구성했습니다.

## 구현 내용

- `GET /api/admin/dashboard?days=7|30|90` 응답에 일별 주문·출고·매출, 상품별 출고 순위, 창고별 재고, 위험 품목, 반품 사유, 최근 6개월 정산, 거래처별 미수 순위를 추가했습니다.
- `GET /api/warehouse/analytics?days=7|30|90`를 추가해 일별 출고 처리량, 출고 대기 경과 시간, 거래처별 대기량, 반품 검사 결과를 제공합니다.
- `GET /api/analytics?days=7|30|90`를 추가해 로그인한 거래처의 주문·거래 금액, 상품별 구매, 월별 원장·결제 배분을 해당 거래처 범위에서만 제공합니다.
- 관리자 운영 현황·주문 이력·재고 정정·반품 처리·정산 조회·입금 배분 화면에 `AreaChart`, `BarChart`, `ComposedChart`, 누적 막대와 가로 순위 그래프를 적용했습니다.
- 창고 출고·반품 화면과 거래처 주문·정산 화면에도 역할별 업무 판단에 필요한 그래프를 배치했습니다.
- 모든 집계는 페이지에 표시된 일부 목록이 아니라 PostgreSQL 전체 대상 데이터에서 계산합니다. 금액은 서버 응답에서 문자열로 유지하고 화면에서만 숫자로 변환합니다.
- 그래프 구현은 프로젝트에 고정한 `recharts@3.8.0`과 SDTPL_ADM 기반 `ChartContainer`를 사용합니다.

## 완료 기준과 검증

- 관리자·창고·거래처 분석 API의 정상 응답과 허용하지 않은 기간의 `400 Bad Request`를 통합 테스트로 검증했습니다.
- `npm.cmd run test:foundation`: 64/64 통과
- `npm.cmd run build --workspace=@b2b-stm/api`: 통과
- `npm.cmd run build --workspace=@b2b-stm/web`: 통과
- `npm.cmd run ui:verify-recent`: 데스크톱 1440×900, 모바일 390×844에서 26/26 통과
- `npm.cmd run repo:verify-public`: 제외 규칙 7개, 공개 후보 376개 경로 통과
- `npm.cmd audit --omit=dev`: 취약점 0건
- 검증 대상에서 가로 넘침, console error, 실패한 내부 요청은 없었습니다.
- 그래프 SVG 렌더링과 대표 화면의 hover tooltip을 실제 브라우저에서 확인했습니다.

## 운영상 주의점

- 정산 그래프의 청구·수금·미수는 확정된 정산만 집계합니다.
- 거래처 그래프는 세션의 `customerId`를 서버가 강제 적용하므로 다른 거래처 데이터를 조회할 수 없습니다.
- 창고 역할은 현재 시스템의 창고 배정 모델이 없으므로 전체 창고 작업 큐를 집계합니다. 창고별 담당자 배정 기능을 도입할 때 같은 경계로 제한해야 합니다.
