# 재사용 가능한 프로젝트 하네스 문서

## 변경 이유

B2B-STM에서 정착한 문서 접근, 설계, 테스트, UI 검증, 운영 검증 방식을 다른 프로젝트에서도 사용할 수 있도록 제품 업무 규칙과 분리된 이식 문서가 필요했습니다.

## 변경 내용

- `docs/harness/README.md`에 문서 묶음의 목적과 적용 순서를 정리했습니다.
- `portable-harness-guide.md`에 저장소 규칙, 지속 문서, 환경 스킬·플러그인, 프로젝트 검증 명령의 네 층 구조를 정의했습니다.
- `plugin-skill-inventory.md`에 실제 사용한 핵심 스킬·플러그인과 조건부 항목을 구분했습니다.
- `bootstrap-checklist.md`에 새 프로젝트 복사, 고유 항목 작성, 설치 확인, 첫 검증, 유지보수 순서를 작성했습니다.
- `harness-manifest.yaml`에 문서 순서, 필수·조건부 스킬, 검증한 플러그인 버전과 교체 항목을 구조화했습니다.
- 새 저장소에 복사할 `AGENTS.md`, 현재 개발 상태, 변경 기록 템플릿을 추가했습니다.

## 범위와 경계

- B2B 주문·재고·출고·정산 관계는 예시의 출처로만 사용하며 범용 템플릿에는 placeholder로 분리했습니다.
- 현재 프로젝트의 DB 접속 정보, 관리자 계정, 샘플 비밀번호, 세션과 Cloudflare URL은 포함하지 않았습니다.
- 사용자 환경의 플러그인 캐시를 저장소에 복사하지 않고 이름·버전·설치 경계만 기록했습니다.
- 현재 프로젝트에는 별도 전용 agent/skill 정의가 없다는 감사 결과를 반영해 존재하지 않는 구성을 문서에 만들지 않았습니다.

## 검증 결과

- 하네스 문서 7개와 변경 기록의 존재를 확인했습니다.
- `harness-manifest.yaml`의 필수 키와 검증된 `harness 1.2.0`, `designlang 13.2.0` 버전을 확인했습니다.
- 템플릿 밖의 Markdown 상대 링크가 실제 파일을 가리키는지 확인했습니다.
- 비밀번호·token·cookie·`DATABASE_URL` 값이 포함되지 않았는지 검색했습니다.
