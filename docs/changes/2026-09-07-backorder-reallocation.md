# 추가 입고 후 미확보 주문 재배정

## 변경 이유

주문 확정 시 재고가 부족하면 확보 가능한 수량만 예약되고 나머지는 미확보로 남았습니다. 이후 입고가 발생해도 해당 주문에 재고를 다시 배정하는 업무 명령과 화면이 없어, 미확보 주문이 계속 대기 상태에 머무는 문제가 있었습니다.

## 변경 내용

### 재배정 트랜잭션

- `POST /api/admin/orders/:orderId/allocate`를 추가했습니다.
- 확정 상태 주문만 재배정할 수 있으며 주문 품목의 `requested_quantity - reserved_quantity`를 미확보 수량으로 계산합니다.
- 주문, 품목, 상품별 재고 잔액을 잠근 뒤 최신 `on_hand_quantity - reserved_quantity` 범위에서만 추가 예약합니다.
- 기존 예약이 있으면 예약 수량을 늘립니다. 기존 예약분이 전량 출고돼 `shipped` 상태여도 새 배정분이 생기면 `active`로 되돌려 창고 출고 대기에 표시합니다.
- 확정 당시 예약이 0이었던 품목은 새 예약을 생성합니다.
- 추가 배정은 `reservation_events`에 실행자와 수량을 남깁니다.
- 같은 `requestId`의 재전송은 원래 결과를 반환하며 재고를 중복 예약하지 않습니다.
- 가용 재고가 없으면 오류로 위장하지 않고 추가 예약 0개와 남은 미확보 수량을 확정 결과로 반환합니다.

### 관리자 주문 화면

- 확정 주문에 미확보 수량이 있을 때 `미확보 재배정` 작업 영역을 표시합니다.
- 현재 미확보 수량과 추가 입고 재고를 확인한다는 업무 영향을 확정 전에 안내합니다.
- 완료 후 추가 예약 수량과 남은 미확보 수량을 표시하고 최신 주문 데이터를 다시 조회합니다.
- 모바일의 기존 6열 품목표를 상품 카드로 교체해 단가·주문·출고·예약·미확보 수량이 잘리지 않게 했습니다.

## 검증 내용

- 재고 5개로 주문 8개를 확정한 뒤 입고 3개를 등록하고 재배정하면 주문 예약과 재고 예약이 모두 8개가 되는지 검증합니다.
- 동일 재배정 요청을 동시에 두 번 보내도 예약과 이벤트가 한 번만 증가하는지 검증합니다.
- 두 미확보 주문이 입고 2개를 동시에 재배정해도 두 응답의 추가 예약 합계가 2개이고 전체 재고 예약이 보유 재고를 넘지 않는지 검증합니다.
- 실제 브라우저에서 주문 8개 접수, 초기 예약 5개, 입고 3개, 미확보 재배정, 출고 3개와 남은 예약 5개를 관리자·창고·거래처 화면에서 확인합니다.
