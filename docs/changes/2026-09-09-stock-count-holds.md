# 재고 실사 보류와 예약 조정

## 변경 이유

실사 중에도 입고·정정·예약 해제·피킹·출고가 진행되면 실측 기준과 시스템 재고가 달라집니다. 실측 부족분이 이미 예약된 수량보다 작을 때 어떤 주문을 해제할지도 일관된 규칙이 필요했습니다.

## 구현 내용

- 창고·SKU별로 하나의 진행 중 실사만 허용하고 시작 시 보유·예약 수량을 저장합니다.
- 진행 중인 SKU의 신규 주문 노출, 주문 확정·재배정, 주문 취소 승인, 입고·정정, 피킹·검수·출고, 정상 반품 복귀를 차단합니다.
- 이미 피킹·검수한 수량이 있으면 실사를 시작하거나 확정할 수 없습니다.
- 실측 수량이 예약보다 부족하면 최근 주문의 미출고 예약부터 부족 수량만큼 해제하고 주문 라인의 예약 수량도 함께 갱신합니다.
- 실측 차이는 재고 정정과 원장에 기록하며, 예약 해제 내역은 실사별 연결 테이블에 보존합니다.
- 실사 시작·확정·취소는 `requestId`로 중복 실행을 방지하고 MFA 감사 조회에 노출합니다.
- 관리자 `/admin/stock-counts`에서 SKU 검색, 보류 시작, 영향 예약 확인, 실측 확정, 보류 해제와 이력 그래프를 제공합니다.

## 동시성 기준

재고를 바꾸는 명령은 `inventory_balances` 행을 잠근 뒤 진행 중 실사를 확인합니다. 실사 확정은 관련 예약·주문 행과 재고 잔액을 잠그고 한 transaction에서 예약 해제, 재고 정정, 원장 기록, 실사 종료를 완료합니다.

## 검증

- 실사 중 중복 시작, 입고, 재고 정정, 재배정, 출고 작업 배정, 주문 취소 승인이 `409`로 차단됨을 PostgreSQL 통합 테스트로 확인했습니다.
- 거래처 주문 카탈로그에서 실사 중 SKU가 제외됨을 확인했습니다.
- 실측 부족 시 최근 주문 예약이 먼저 해제되고 재고 잔액과 주문 라인 수량이 일치함을 확인했습니다.
