# 주문 목록 서버 페이지 처리

작성일: 2026-09-07

## 변경 이유

거래처 주문 내역, 관리자 처리 목록, 관리자 주문 이력이 조건에 맞는 모든 주문과 주문행을 한 응답으로 조립했습니다. 목표 규모인 주문 100,000건에서는 DB 연산량, API 메모리, JSON 전송량이 제한되지 않아 실제 운영과 성능 시험을 진행할 수 없는 구조였습니다.

## 변경 내용

- 세 주문 조회 API에 `page`와 `pageSize`를 추가했습니다.
- 기본 페이지 크기는 50건이며 한 요청의 최대 크기는 100건입니다.
- 응답에 `items`, `page`, `pageSize`, `total`, `totalPages`를 제공합니다.
- 주문 상세 JSON은 선택된 페이지의 주문에 대해서만 조립합니다.
- `page`와 `pageSize` 중 하나만 전달하거나 범위를 벗어난 값은 `400`으로 거부합니다.
- 관리자 주문 관리, 관리자 주문 이력, 거래처 주문 이력 화면에 공통 이전·다음 이동 UI를 연결했습니다.
- 현재 페이지가 처리 결과로 사라지면 마지막 유효 페이지로 자동 이동합니다.

## 검증 결과

- 페이지 입력·metadata 단위 테스트 3건이 통과했습니다.
- 실제 NestJS HTTP에서 1건 페이지와 최대 크기 초과 `400`을 확인했습니다.
- 전체 foundation 48건과 API·웹 production build가 통과했습니다.
- 실제 Chromium에서 거래처 주문 이력, 창고 출고 큐, 관리자 운영·주문 화면 흐름이 통과했습니다.
- 권한·성능 스모크 300건에서 오류 0건, 병렬 브라우저 검증이 함께 실행된 조건의 전체 p95는 176.6ms였습니다.
