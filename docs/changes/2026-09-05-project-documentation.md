# 프로젝트 문서 기반 구성

날짜: 2026-09-05.

## 이유와 기존 상태

사용자가 기존 프로젝트처럼 `docs/`에 제반 사항을 기록하도록 요청했습니다.
작업 전 B2B 루트에는 `.git`과 참고 테마 `SDTPL_ADM/`이 있었으며 제품 문서 기반은 없었습니다.
대화에만 있는 제안이 확정 요구사항으로 혼동되지 않도록 상태와 결정 근거를 분리했습니다.
버그 수정이 아닌 신규 문서 구성입니다.

## 변경

- 루트 `AGENTS.md`에 공통 작업 규칙과 프로젝트·테마 경계를 기록했습니다.
- `docs/`에 문서 안내, 공통 원칙, 접근 순서, 도구·테마 정책을 추가했습니다.
- 프로젝트 개요·현재 상태·로드맵·도메인·업무 시나리오·의사결정을 기록했습니다.
- 부동산 전용 관계를 B2B의 주문·재고·출고·정산 관계 초안으로 교체했습니다.
- 업종 확정과 미승인 업무 정책을 구분했습니다.

## 검증

- `docs/` 문서 11개와 루트 `AGENTS.md` 생성을 확인했습니다.
- PowerShell로 문서 전체를 UTF-8로 읽어 내부 상대 링크의 대상 존재 여부를 검사했습니다. 깨진 링크 0개, 대체 문자 0개였습니다.
- `SDTPL_ADM/`에서 작업 전후 `git status --short` 출력이 모두 비어 있음을 확인했습니다. 테마 원본 변경은 없습니다.
- 루트 Git 상태에서 신규 `AGENTS.md`와 `docs/`를 확인했습니다. 기존 `SDTPL_ADM/`의 untracked 상태는 유지했습니다.
- 제품 코드 변경이 없어 앱 테스트·빌드는 실행하지 않았습니다. 커밋·push는 수행하지 않았습니다.

## 후속 기획: 주문·재고 확보 정책

- 이유: 사용자의 계속 진행 요청에 따라 주문 승인과 예약 시점을 구체화했습니다. 접수와 공급 확약의 혼동, 출고·취소 경합, 실사 부족 처리가 설계의 주요 쟁점입니다.
- 변경: 승인 방식 3가지 비교와 관리자 확정 시 예약하는 제안, 부분 출고 선택, 잔량 배정·취소, 실사 부족 보류 정책을 추가했습니다. 안내·업무 시나리오·의사결정·인계를 함께 갱신했습니다.
- 상태: 사용자 검토용 제안이며 구현은 시작하지 않았습니다.
- 검증: PowerShell로 문서 12개와 내부 링크 22개를 확인했고 깨진 링크는 없었습니다. 수량 예시는 문서 내 정합성 검토이며 제품 실행 검증이 아닙니다.

## 주문 정책 확정과 반품·정산 기획

- 근거: 주문 정책 확정 및 반품·정산 구체화 질문에 사용자 `오케이` 응답.
- 변경: 주문 정책을 확정으로 갱신하고 개요·업무 시나리오·의사결정·인계의 이전 대기 상태를 수정했습니다.
- 제안: 반품 회수·검수와 금액 차감 분리, 마감 보존과 후속 조정, 입금 배분·취소, 크레딧 사용·실제 환불 기록을 새 문서로 구체화했습니다.
- 검증: 문서 13개, 상대 링크 25개 검사 오류 0개. 이전 주문 답변 대기 문구를 검색해 해소했으며 테마 원본 Git 상태는 변경 없이 깨끗합니다.
- 미검증: 제품 구현·테스트는 수행하지 않았습니다. 반품·정산 정책과 전체 기획은 아직 승인 전입니다.

## 반품·정산 확정과 운영 기준 제안

- 근거: 반품·정산 정책 문서와 요약을 제시한 질문에 사용자 `오케이` 응답.
- 변경: 반품·정산 정책과 관련 인계·개요·결정 상태를 확정으로 갱신했습니다. 세금·반올림 등 문서에 명시한 별도 검토 사항은 미확정 상태를 유지합니다.
- 제안: 첫 운영 버전의 단일 유통사·창고 모델, 거래처 100곳·SKU 1,000개·동시 사용자 30명 기준, 역할 분리와 기능 경계, 성능·복구·운영 인수 목표를 기록했습니다.
- 검증: 문서 14개, 내부 링크 26개 검사 오류 0개. 테마 원본 Git 상태는 깨끗합니다.
- 미검증: 운영 수치는 제안 목표이며 성능·복구 실측 결과가 아닙니다. 구현·설치·배포는 수행하지 않았습니다.

## 운영 기준 확정과 테마 사본 준비

- 근거: 첫 운영 버전 규모·범위 검토에 사용자 `좋아` 응답. 최초 요청의 별도 테마 사본 사용 지시에 따라 복사를 진행했습니다.
- 변경: 운영 모델·권한·범위·검수 목표를 확정으로 갱신했습니다. 목표 승인과 실제 성능·복구 달성을 구분합니다.
- 사본: `theme-preview/`에 원본의 `.git`, 환경 파일, 설치·빌드 산출물을 제외한 418개 파일을 복사했습니다. 원본의 참고 docs와 샘플 화면도 포함되어 있으며 B2B 업무 구현 또는 기획 승인으로 간주하지 않습니다.
- 검증: 418개 파일 각각 SHA-256 해시가 원본과 일치했습니다. 원본 `git status --short` 출력은 비어 있습니다.
- 미완료: 테마 의존성 설치·실행·시각 검수·확정은 아직 수행하지 않았습니다. 제품 코드 변경은 없습니다.

## 테마 실행 준비와 검증

- 근거: 사용자 계속 진행 요청에 따라 사본 실행과 확인을 진행했습니다.
- 변경: `theme-preview/`에 잠금 파일 기준 의존성을 설치하고 로컬 3100 포트 개발 서버를 실행했습니다. 전역 pnpm이 없어 `npx.cmd --yes pnpm@10`을 사용했습니다.
- 검증: 빌드·TypeScript·101개 정적 페이지 생성 통과. lint 오류 0·기존 경고 28. 기본·ecommerce·payment 경로 HTTP 200 확인. 잠금 파일 원본과 일치, 테마 원본 Git 변경 없음.
- 제한: 연결된 브라우저와 in-app browser 모두 사용할 수 없어 시각 검수는 미완료입니다. UI/UX 검색 도구도 Python 부재로 실행하지 못했습니다. 다음 작업은 브라우저 연결 후 대표 화면 검토입니다.
- 인계: `docs/overview/theme-review.md`에 실행 명령·URL·검증 범위를 기록했습니다. 제품 업무 구현과 테마 확정은 진행하지 않았습니다.

## 밝은 테마 적용

- 이유: 사용자 요청으로 라이트 테마를 확정했습니다. 기본값만 변경하면 이전 dark 저장값이나 OS 설정이 남을 수 있어 `forcedTheme`을 적용했습니다.
- 변경: 사본 루트 ThemeProvider와 알림을 light로 고정하고 헤더의 모드 전환 버튼을 제거했습니다.
- 검증: Playwright Chromium 설치 후 `node e2e/verify-light.cjs` 통과. OS·저장값 dark 조건에서도 light 유지, 전환 버튼 없음, 데스크톱·모바일 캡처 확인. 변경 TSX 두 파일 ESLint 통과.
- 제한: 전체 화면 조작성·글꼴·차트 검수는 별도이며 이번 작업은 밝은 모드 적용입니다. 원본에는 변경하지 않았습니다.

## 역할별 화면 구성과 기획 완료 기준

- 근거: 사용자가 화면 구성·남은 상세 설계의 계속 진행을 요청했습니다.
- 변경: 관리자·거래처·창고의 메뉴와 제안 경로, 주문 수량 표시, 반품·정산 연결, 동시 작업·통신 실패·권한 오류 처리를 문서화했습니다. 남은 기획을 대표 화면·업무·기술·운영·구현 계획 묶음으로 정리했습니다.
- 설계 판단: 한 웹에서 작업 공간을 나눠 공통 테마를 공유하되 서버 권한을 분리하는 안을 제안합니다. 관리자 표를 그대로 모바일에 축소하지 않고 창고 작업 수량과 보류 사유에 집중합니다.
- 검증: docs의 UTF-8 읽기와 내부 링크 검사 통과. 원본 테마 Git 상태 변경 없음. 확정 업무와 화면 제안을 구분해 검토했습니다.
- 미완료: 화면 설계안 승인, 대표 화면 제작과 화면별 Playwright 검수. 이번에는 제품·테마 코드를 변경하지 않았습니다.

## 검토용 대표 화면 3개 구현

- 근거: 사용자 `오케이 진행해` 및 계속 진행 요청으로 화면 제작을 승인했습니다.

- 검증: Playwright 3개 경로·360px 페이지 폭·수량 입력·3개 확인 흐름 통과, 캡처 6개 생성과 대표 캡처 확인. 변경 디렉터리 ESLint 및 Next 빌드·TypeScript 통과. 최종 문구 변경 후 Playwright 재검증 통과. 원본 테마 Git 변경 없음.
- 수정 이유: 확정 전 실제 예약/미확보와 확정 후 부족 예상을 구분했고 수량 단위 줄바꿈을 방지했습니다. 생성 타입 불일치는 빌드로 갱신했으며 캡처의 조기 caret 조작에 의한 hydration 경고는 검증 순서를 보정했습니다.
- 제한: 화면 내 메모리 상태만 사용합니다. API·DB·인증·실제 업무 저장은 미구현이며 전체 제품 기획 승인도 별도입니다.

## 인증·금액·운영 통합 설계
