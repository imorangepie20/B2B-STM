# 프로젝트 개요

기록일: 2026-09-05. 최종 갱신: 2026-09-09. 상태: 핵심 운영 흐름·예외 처리·역할별 통계·운영 인수 스모크와 포트폴리오 자료 구현 완료. 현장 물류와 배포 운영의 후속 범위를 개발 중입니다.

## 확정된 목표

위시켓 포트폴리오로 제시할 수 있는 중소 유통업체용 B2B 주문·재고·출고·정산 시스템을 개발합니다.
데모 수준이 아닌 실제 업무 사용이 목표이며, 규모보다 업무 흐름의 완결성과 운영 안정성을 우선합니다.
대상 업종은 카페·음식점용 비식품 포장재·소모품 도매업입니다. 컵·뚜껑·용기·봉투 등을 기준 상품으로 제안했습니다.

거래처 주문 포털, 창고 담당자 모바일, 관리자 화면을 연결합니다.
부분 출고·반품·재고 정정·동시 주문·중복 요청 처리는 필수입니다.
기획 확정 후 구현하며 별도 테마 사본에서 테마를 먼저 정합니다.

관리자 확인 후 주문 확정, 확정 시 재고 예약, 부분 출고 선택과 잔량 처리는 사용자 승인으로 확정했습니다.
반품 검수와 금액 차감 분리, 출고 기준 월 마감, 마감 후 조정, 입금 배분·취소와 실제 환불 기록도 확정했습니다.

## 확정된 운영 모델

- 유통사 한 곳, 창고 한 곳, 여러 거래처.
- 상품별 고정 포장 단위. 규격이 다르면 별도 SKU. 낱개 판매는 초기 제외.
- 거래처별 단가, 관리자 거래처 등록 및 계정 초대. 월 정산 정책 자체는 확정했습니다.

## 첫 운영 버전 범위

| 영역 | 첫 운영 버전 제안 |
|---|---|
| 거래처 포털 | 상품·단가 조회, 주문, 잔량·출고 조회, 취소·반품 요청, 정산·입금 내역 |
| 창고 모바일 | 입고, 피킹·검수, 부분 출고, 반품 검수, 실사·재고 정정 |
| 관리자 | 거래처·상품·포장 단위·가격, 주문 배정, 재고 원장, 정산·입금 배분, 권한·감사 이력 |
| 공급 기반 | 기본 공급처·입고 기록 |
| 운영 기반 | 중복 요청 방지, 동시성 제어, 오류 복구, 백업·복원, 모니터링, 초기 데이터 가져오기 |

현재 거래처 포털, 관리자 주문·재고·실사·반품·세금 정산·거래명세서·입금·환불, 창고 피킹·검수·출고·배송·인도·반품 검수, 계정·MFA·감사, 초기 이관과 로컬 복원·운영 스모크, 첨부와 알림을 구현했습니다. 창고 입고 초안과 실배포 모니터링은 남아 있습니다.

복잡한 구매·매입 회계, 다중 창고, 배송 최적화, 외부 회계·택배·전자세금계산서 연동,
오프라인 출고는 첫 운영 버전 기준 승인에 따라 후속 범위로 분리합니다.

## 완료 기준

- 세 역할에서 같은 주문의 재고 확보·출고·반품·정산 결과가 일치합니다.
- 동시 주문에서도 가용 재고를 초과 배정하지 않습니다.
- 동일 요청 재전송으로 주문·출고·입금이 중복 반영되지 않습니다.
- 출고·반품·재고 정정에 원장, 사유, 작업자와 이력을 남깁니다.
- 거래처 간 주문·단가·정산 접근을 차단하고 역할별 권한을 검증합니다.
- 확정 후 응답 유실, 서버 재시작, 재시도에서도 결과를 확인하고 업무를 이어갑니다.
- 실제 PostgreSQL 통합 테스트와 역할별 브라우저 업무 시나리오를 검증합니다.
- 백업 복원 리허설과 운영 인수 시나리오를 통과합니다.
- 예상 사용자·상품·주문량을 정한 뒤 처리량·응답시간·복구 목표를 수치화하고 검증합니다.

역할별 업무 E2E, 실제 PostgreSQL 통합 테스트, DB·운영 정합성 검사, 백업 복원 리허설과 로컬 권한·동시 조회 스모크를 수행했습니다. 완료 기준별 증거와 미실행 목표 규모 성능 시험은 [운영 인수 증빙](../portfolio/operational-acceptance-evidence.md)에서 구분합니다.
