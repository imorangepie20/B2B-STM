# 기획·구현 현행 점검표

최초 작성일: 2026-09-05. 최종 갱신: 2026-09-09.

## 확정되고 구현된 기준

- 카페·음식점용 비식품 포장재·소모품 도매업과 단일 창고 운영 모델
- 관리자 확정 시 재고 예약, 부족 잔량 재배정, 부분 출고와 취소 요청
- 원출고 기반 반품, 정상·불량 검수, 반품 차감과 마감 후 조정
- 월 정산, 입금 등록·배분·취소, 역할별 데이터 접근 경계
- 주문별 창고 담당 시작·경쟁 차단·사유 있는 반납과 완료 자동 종료
- 예약별 피킹·검수 수량, 정정·인계·취소 이력과 검수 수량 이내 출고
- 출고별 배송 일정·운송장·배송 실패 재예약·인도 완료 증빙과 역할별 조회
- Next.js·NestJS·PostgreSQL, 기존 Docker DB 재사용, 라이트 `SDTPL_ADM` 테마
- 실제 DB 통합 테스트, Playwright 업무 흐름, 운영 스모크와 백업 복원 리허설

## 확정됐지만 구현이 남은 기준

- 첨부파일, 업무 내보내기, 알림 실패 재처리
- 실제 배포 환경의 모니터링·장애 대응·RPO/RTO 측정

## 후속 범위

- 다중 창고, 로트·유통기한, 배송 최적화
- 은행·택배·회계·전자세금계산서 자동 연동
- 카메라 바코드 인식과 전용 PDA 연동
- 주문 100,000건·동시 사용자 30명·30분 본 시험은 사용자 요청으로 중단

상세 우선순위와 완료 상태는 [제품 구현 현황과 후속 계획](../superpowers/plans/2026-09-05-product-delivery-plan.md), 검증 증거는 [운영 인수 증빙](../portfolio/operational-acceptance-evidence.md)을 기준으로 합니다.
