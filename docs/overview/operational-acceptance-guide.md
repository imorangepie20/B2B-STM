# 운영 인수 스모크 점검 안내

## 실행 조건

- 개발 DB `b2b_stm`에 `npm.cmd run demo:seed`로 실제 데모 데이터가 준비되어 있어야 합니다.
- API가 `http://127.0.0.1:3200`에서 실행 중이어야 합니다.
- `.env.local`의 `DATABASE_URL`은 로컬 `b2b_stm`을 가리켜야 합니다. 다른 DB에는 검증 세션을 만들지 않습니다.

## 실행 명령

```powershell
npm.cmd run ops:acceptance-smoke
```

기본값은 30개 동시 작업자와 300개 조회 요청입니다. 필요하면 다음 환경 변수로 조절합니다.

| 환경 변수 | 기본값 | 의미 |
|---|---:|---|
| `API_ORIGIN` | `http://127.0.0.1:3200` | 점검할 API origin |
| `ACCEPTANCE_CONCURRENCY` | `30` | 동시 작업자 수, 최대 100 |
| `ACCEPTANCE_REQUESTS` | `300` | 전체 조회 요청 수, 최대 10,000 |
| `ACCEPTANCE_READ_P95_MS` | `1000` | 읽기 API p95 허용값 |
| `ACCEPTANCE_ERROR_RATE` | `0.001` | 예상하지 못한 상태 코드 허용 비율 |

## 확인 내용

권한 점검은 비로그인, 거래처, 창고, MFA 미확인 운영자, MFA 확인 운영자의 허용·거부 상태 코드를 확인합니다. 성능 점검은 관리자 대시보드·기준정보·재고·주문·정산, 창고 출고·반품 큐, 거래처 상품·주문·원장·입금 조회를 고르게 호출합니다.

검증용 세션만 일시적으로 추가하고 `finally` 단계에서 삭제합니다. 주문, 주문행, 재고, 출고, 반품, 정산, 입금은 변경하지 않습니다. 결과 JSON의 `permissions`, `performance.overall`, `performance.byEndpoint`, `failures`를 함께 확인합니다.

## 판정 범위

이 명령은 개발 중 권한과 응답 성능 회귀를 찾는 짧은 로컬 스모크입니다. [첫 운영 버전 기준](operating-baseline.md)의 거래처 100개, SKU 1,000개, 주문 100,000건, 주문행 1,000,000건과 30분 지속 부하를 증명하지 않습니다. 실제 배포 환경의 사양과 목표 규모 데이터로 별도 본 시험을 실행한 뒤 운영 성능을 판정합니다.
