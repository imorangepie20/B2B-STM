## 작업 방식

- 사용자가 TDD를 최소화하도록 요청했습니다. 핵심 실패 경계만 짧게 검증하고 기능마다 선행 테스트를 만들지 않습니다.
- 기존 테스트는 삭제하지 않습니다.
- 변경 범위의 빌드와 핵심 동작을 먼저 짧게 검증합니다.
- 장시간 전체 회귀·브라우저·성능 검증은 큰 기능 완료 시점 또는 사용자 요청 때만 실행합니다.
- 긴 파일 전체 읽기, 같은 빌드·테스트 반복, 불필요한 진행 설명을 피합니다.
- 완성도를 낮추지 않고 근본 원인과 실제 업무 흐름을 기준으로 구현합니다.
- 의미 있는 변경은 변경 이유·내용·검증 결과와 함께 `docs/`에 기록합니다.
