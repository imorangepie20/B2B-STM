# 화면 구성과 역할별 업무 연결

작성일: 2026-09-05. 최종 갱신: 2026-09-09. 라이트 테마와 역할별 제품 화면을 구현했습니다. 아래 표는 현재 경로와 후속 화면을 함께 표시합니다.

## 설계 방향

관리자는 예외와 대기 업무를 빠르게 찾고, 거래처는 반복 주문과 진행 조회를 쉽게 하며,
창고는 현재 맡은 작업과 수량 확인에 집중하도록 화면을 구분합니다. 세 화면은 같은 주문·출고·반품 기록을 참조합니다.

검토한 대안은 모든 역할에 같은 관리자 메뉴를 제공하는 방식, 역할별 앱을 완전히 분리하는 방식,
하나의 웹에서 역할별 작업 공간을 나누는 방식입니다. 첫 버전은 세 번째를 제안합니다.
공통 테마·인증·컴포넌트를 공유하면서 역할별 메뉴와 화면 밀도를 구분할 수 있습니다.
API는 역할과 데이터 범위를 검증하며 작업 공간 선택은 권한 부여 수단이 아닙니다.

## 공통 화면 규칙

- 밝은 배경과 기존 shadcn 컴포넌트를 사용합니다. 상태는 색상과 함께 한국어 텍스트로 표시합니다.
- 통계 카드만 나열하지 않고 담당자가 처리할 항목과 관련 목록 링크를 우선 제공합니다.
- 조회 실패를 빈 목록·0원·0건으로 표시하지 않습니다. 로딩·빈 결과·권한 없음·조회 실패를 구분합니다.
- 처리 중 중복 버튼 입력을 막되, 중복 방지는 서버에서도 보장합니다.
- 응답이 끊기면 완료로 단정하거나 새 작업을 만들지 않고 처리 결과 확인과 같은 요청 재시도를 제공합니다.
- 다른 담당자가 변경했으면 최신 상태와 달라진 내용을 보여주고 재확인하게 합니다. 작성 중 입력은 가능한 범위에서 유지합니다.
- 목록은 서버 검색·필터·페이지 처리를 사용합니다. 현재 화면 state로 유지하며 URL query 보존은 후속 개선입니다.
- 수량은 `7박스`처럼 단위를 함께 표시합니다. 금액과 날짜는 업무 기준에 맞게 일관되게 표시합니다.
- 확인창에는 작업 대상·수량·금액·영향을 구체적으로 표시하고 취소·정정에는 사유를 받습니다.
- 모바일 주요 작업 버튼은 44px 이상을 목표로 하며 좁은 화면에서 확정 버튼과 입력란이 겹치지 않게 합니다.
- 원본 캡처에서 보인 기본 serif 글꼴은 제품 기준으로 확정하지 않습니다. 한글용 글꼴·가독성은 대표 화면에서 별도로 검수합니다.

## 관리자 작업 공간

운영·정산·시스템 관리자 권한에 따라 아래 메뉴를 표시합니다. 관리자 화면에 들어왔다고 모든 업무 권한을 주지 않습니다.

| 메뉴 / 현재 URL | 주요 내용 | 핵심 동작 |
|---|---|---|
| 업무 현황 `/admin` | 확인 대기 주문, 부족 재고, 출고 보류, 반품 금액 대기, 미수 | 수치 선택 시 해당 조건의 목록으로 이동 |
| 주문 `/admin/orders` | 거래처·주문일·상태·확보·출고·대기 수량 | 확정, 배정, 잔량 취소 처리 |
| 주문 이력 `/admin/order-history` | 완료·취소 주문과 출고·매출 원장 | 주문·출고·취소 근거 조회 |
| 재고 정정 `/admin/inventory-adjustments` | 정상·예약·가용 재고 | 사유가 있는 수량 정정과 원장 조회 |
| 입고 `/admin` | 공급처·창고·상품·수량 | 빠른 입고 확정과 재고 반영 |
| 반품 차감 `/admin/return-credits` | 검수 결과·불량 사유·차감 대기 | 불량 보류, 금액 차감 확정 |
| 정산 `/admin/settlements` | 거래처·귀속월·초안·확정·잔액 | 초안 검토·마감, 출고/조정 근거 조회 |
| 입금·배분 `/admin/payments` | 입금·배분·미배분 | 등록·배분·역처리·입금 취소 |
| 기준 정보·단가 `/admin/pricing` | 거래처·상품·판매 단위·공급처·창고·단가 | 등록·변경·비활성화 |
| 계정 `/admin/accounts` | 내부·거래처 계정과 역할 | 초대·재설정·활성 상태 변경 |
| 계정 보안 `/admin/account-security` | MFA 등록 계정 | MFA 기기 초기화와 복구 |
| 감사 `/admin/audit-events` | 수량·금액·계정·출고 작업 이력 | 기간·유형·작업자·사유 검색 |
| 데이터 가져오기 `/admin/imports` | 파일·미리보기·오류·실행 결과 | 기준 데이터 이관, 중복 방지·결과 대조 |

### 주문 상세의 핵심 구성

상단에는 주문번호·거래처·접수/확정 일시·부분 출고 조건을 표시합니다.
품목별 `주문 / 취소 / 출고 / 예약 / 미확보` 수량을 한 표에서 비교합니다.
관리자는 부족 사유와 기존 대기 주문을 보면서 예약 배정을 확정합니다.
하단에서 출고 이력·반품·정산과 작업자별 처리 이력을 추적합니다.
주문에 단일 상태 배지만 표시해 부분 출고·잔량 대기를 숨기지 않습니다.

## 거래처 포털

| 메뉴 / 현재 URL | 주요 내용 | 핵심 동작 |
|---|---|---|
| 상품 주문 `/portal/orders` | 허용 상품·창고·거래처 단가 | 수량 입력, 주문 접수 |
| 주문 내역 `/portal/orders/history` | 접수·확정·예약·출고·대기·취소 수량 | 검색, 상태 필터, 상세 조회 |
| 반품 `/portal/returns` | 원출고·반품 수량·사유·진행 | 출고에서 반품 요청, 회수·차감 조회 |
| 정산 `/portal/settlements` | 월 정산·입금 배분·미수 | 출고·반품·입금 근거 조회 |

재주문은 과거 수량을 새 장바구니로 복사한 뒤 현재 상품 판매 여부·단가를 다시 확인합니다.
이전 단가로 새 주문을 자동 확정하지 않습니다. 가격이 바뀌었으면 제출 전에 차이를 보여줍니다.
전체 창고 재고나 다른 거래처 예약은 노출하지 않고 자신의 주문 확보·대기 수량을 표시합니다.
세금 포함 표시·배송 정보 수정 규칙은 상세 정책에서 확정합니다.

## 창고 모바일

현재 창고 메뉴는 `출고 대기 / 반품 검수` 두 업무로 구성합니다. 입고·피킹 검수·실사는 후속 화면으로 추가합니다. 프로필·로그아웃은 보조 메뉴에 배치하며 관리자용 표 전체를 모바일에 축소해 넣지 않습니다.

| 화면 / 현재 URL | 표시 내용 | 핵심 동작 |
|---|---|---|
| 출고 작업 `/warehouse/shipments` | 주문별 대기·내 작업·타 담당·예약·피킹·검수 잔량 | 검색, 담당 시작·반납, 피킹 저장, 검수 완료, 부분 출고 확정 |
| 반품 `/warehouse/returns` | 반품 요청·도착 잔량·검수 결과 | 분할 입고, 정상/불량 구분과 사유 기록 |
| 입고·피킹 검수·실사 | 부분 완료 | 피킹·검수와 관리자 SKU 실사 보류 구현, 모바일 입고 후속 |

작업 시작 시 서버에서 담당자를 확정합니다. 이미 다른 담당자가 맡았다면 이를 표시하고 중복 시작하지 않습니다.
작업 인계는 현재 담당자가 사유를 기록해 반납한 뒤 다음 담당자가 다시 시작하는 방식으로 구현했습니다.
출고 확정 전 대상 거래처·예약 잔량·이번 출고·출고 후 잔량을 요약합니다. 피킹·검수는 출고 대기 화면에서, 출고 후 배송 일정·운송장·인도 증빙은 배송 관리 화면에서 처리합니다.
스캔 실패 시 수동 상품 검색과 수량 입력을 제공하며 통신 실패 중에는 확정 완료로 보이지 않게 합니다.

## 세 화면의 연결 검수

| 사건 | 거래처 | 관리자 | 창고 |
|---|---|---|---|
| 10박스 접수 | 접수 완료·공급 확정 전 표시 | 확인 대기 1건 | 출고 작업 없음 |
| 7박스 확보, 부분 출고 허용 | 확보 7·대기 3 | 예약 7·미확보 3 | 출고 대상 7 |
| 7박스 출고 확정 | 출고 7·대기 3 | 출고 내역·정산 근거 생성 | 작업 완료 |
| 잔량 3 취소 | 취소 요청/확정 구분 | 출고 경합 검증 후 취소 | 해당 잔량 새 작업 보류 |
| 출고분 1 반품 회수 | 회수·검수 진행 조회 | 인정 금액 확정 대기 | 도착 1·검수 수량 기록 |
| 차감과 정산 확정 | 명세와 실제 잔액 조회 | 출고·반품·입금 근거 확인 | 금액 변경 권한 없음 |

화면 간 값의 일치는 서버 저장 결과로 검증합니다. 갱신 시점·자동 새로고침 방식은 기술 설계에서 정합니다.

## 대표 화면 구현 결과

1. 관리자 주문 상세: 수량 분리와 부분 출고·취소 예외가 읽히는지 확인.
2. 거래처 상품 주문·장바구니: 단위·단가·부분 출고 조건이 명확한지 확인.
3. 창고 출고 작업: 모바일 수량 입력과 확인·실패 복구가 가능한지 확인.
4. 반품 상세와 정산 상세: 재고 상태와 금액 상태, 근거 연결을 확인.

관리자·거래처·창고 대표 화면은 실제 API와 PostgreSQL 데이터에 연결했습니다. 최신 데스크톱·모바일 캡처와 검증 결과는 [대표 화면 검토 결과](../overview/screen-preview-results.md)와 [최근 화면 시각 검증](../changes/2026-09-09-recent-pages-visual-qa.md)을 기준으로 합니다.
