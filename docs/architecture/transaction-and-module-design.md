# 기술 구조와 정합성 설계

최초 설계: 2026-09-05. 최종 갱신: 2026-09-09. 핵심 transaction·잠금·중복 방지 구조와 피킹·검수·실사 보류를 구현했습니다. 환불, outbox와 실제 배포 운영은 남아 있습니다.

## 구조 선택

Next.js 웹, NestJS 업무 API, PostgreSQL 데이터베이스를 제안합니다.
Next.js만으로 전체 기능을 구성하는 대안은 배포 단위가 적지만 UI와 독립된 업무 경계를 별도로 관리해야 합니다.
서비스별 DB를 분리하는 대안은 주문·재고·정산 사이의 분산 실패 복구 부담이 큽니다.
따라서 하나의 NestJS 앱에서 업무 모듈을 나누고 하나의 PostgreSQL 트랜잭션으로 핵심 변경을 묶습니다.
이는 제품 규모·정합성 요구에 따른 설계 판단이며 프레임워크의 강제 사항은 아닙니다.

NestJS는 모듈의 import/export로 provider 경계를 구성할 수 있습니다. 이를 업무 기능 경계로 사용합니다.
근거: [NestJS Modules](https://docs.nestjs.com/modules).

## 저장소와 실행 경계

```text
apps/web             Next.js 역할별 화면
apps/api             NestJS 업무 API와 작업 실행기
packages/contracts   요청·응답 계약 (DB 모델 직접 노출 금지)
docs                 프로젝트 기준 문서
theme-preview        기획 검토 사본
SDTPL_ADM            보존할 테마 원본
```

제품 폴더와 npm workspace를 구성했습니다. DB는 `pg`와 명시적 SQL migration을 사용하고 인증은 서버 세션·CSRF·TOTP MFA로 구현했습니다.
원본의 모든 샘플 경로를 제품으로 복사하지 않고 확정 테마와 필요한 컴포넌트만 반영했습니다.
웹은 업무 DB를 직접 변경하지 않습니다. 예약·출고·차감·입금 규칙은 API가 소유합니다.

## 업무 모듈

| 모듈 | 책임 |
|---|---|
| Identity | 사용자·거래처 소속·역할·계정 차단 |
| Catalog | 상품·고정 포장 단위·공급처·거래 단가 |
| Orders | 접수·확정·취소·가격 및 단위 스냅샷 |
| Inventory | SKU별 잔액·예약·입고·실사·정정·불량 이동 |
| Fulfillment | 작업 담당·피킹·검수·출고·인도 기록 |
| Returns | 원출고 참조·회수·검수·인정 수량 |
| Receivables | 출고 거래 내역·차감·월 마감·입금·배분·환불 |
| Audit / Jobs | 감사 이력·중복 요청·비동기 작업 결과 |

출고 확정 서비스가 필요한 모듈의 명시적 인터페이스를 호출하며 동일 트랜잭션 객체를 전달합니다.
모듈이 각각 별도 커넥션으로 커밋하지 않습니다. HTTP 컨트롤러가 다른 컨트롤러를 호출하지 않습니다.

## 원장과 상태

- 재고 원장은 입고·출고·반품 복귀·불량 이동·실사 정정의 수량 변화를 보존합니다.
- SKU 잔액은 원장과 같은 트랜잭션에서 갱신합니다. 원장 합계와 잔액의 대조 검증을 둡니다.
- 예약은 실물 증감과 분리합니다. 예약·해제 이력과 현재 예약 수량을 보존합니다.
- 정산 원장은 출고 거래와 반품 차감, 기초 미수 등 출처를 참조합니다. 월 정산은 원장을 중복 소비하지 않습니다.
- 입금·배분·환불은 별도 기록입니다. 원기록을 삭제하지 않고 취소 참조로 역처리합니다.
- 상태 수정은 범용 `PATCH status` 대신 확정·취소·출고 등 명시적 업무 명령으로 제한합니다.
- 주문 진행·물류 진행·반품 검수·차감 확정·입금 상태를 하나의 상태값에 섞지 않습니다.

## 트랜잭션 단위

| 명령 | 함께 확정할 내용 |
|---|---|
| 주문 접수 | 가격·단위 스냅샷, 주문/품목, 중복 방지 결과, 감사 |
| 주문 확정·배정 | 주문 버전 검증, 가용 재고 검증, 예약·잔량, 감사 |
| 출고 확정 | 작업·검수·취소 보류 검사, 예약 해제, 실물 차감, 출고 원장, 정산 대상 거래, 감사 |
| 반품 검수 | 실물 도착 잔량 검증, 검수 결과, 정상/불량 재고 이동, 감사 |
| 반품 금액 확정 | 미인정 잔량 검증, 차감 거래, 귀속 기간, 감사 |
| 입금 배분/취소 | 거래처·원금·잔액 검사, 배분/역처리, 감사 |
| 실사 정정 | 관련 작업 보류 검증, 예약 재조정, 실측 반영 원장, 보류 해제 조건, 감사 |

외부 파일 업로드·메일 발송·장시간 내보내기를 트랜잭션 잠금 안에서 실행하지 않습니다.
업무 커밋과 함께 outbox 작업을 기록하고 별도 실행기가 처리합니다. 재처리 가능한 작업 ID와 결과를 보존합니다.
외부 알림 실패는 이미 완료한 출고를 되돌리지 않습니다.

## 동시성

PostgreSQL 행 잠금으로 충돌하는 재고·주문·잔액 변경을 직렬화합니다. 행 잠금은 교착 가능성이 있어 일관된 잠금 순서와 실패 재시도가 필요합니다.
근거: [PostgreSQL Explicit Locking](https://www.postgresql.org/docs/17/explicit-locking.html).

- 첫 버전은 거래처별 업무 잠금 행을 먼저 잠그고, 필요한 SKU 잔액을 SKU ID 오름차순으로 잠그는 안입니다.
- 여러 거래처 주문을 한 작업에서 변경한다면 거래처 ID를 정렬해 먼저 잠급니다. 그 다음 SKU, 업무 상세 행 순서를 지킵니다.
- 입고처럼 거래처가 없는 명령은 SKU부터 잠그며 이후 거래처 잠금을 획득하지 않습니다.
- 모든 관련 명령이 같은 규약을 사용해야 합니다. 일부 endpoint만 잠그는 방식은 허용하지 않습니다.
- 대기 후 잠금을 얻으면 상태와 가용 수량을 다시 읽습니다. 화면에 표시했던 재고를 신뢰하지 않습니다.
- 정정·확정에는 expectedVersion을 받아 이전 화면의 변경을 감지합니다. 다른 담당자 변경을 자동 덮어쓰지 않습니다.
- 교착·직렬화 실패만 최대 3회 제한 재시도하는 안입니다. 도메인 오류와 권한 오류는 자동 재시도하지 않습니다.
- 잠금 대기 제한과 거래처 단위 직렬화의 처리량은 부하 검사 후 수치화합니다.

## 중복 요청과 응답 유실

- 변경 요청은 클라이언트 생성 요청 ID를 사용합니다. 사용자·명령 종류·요청 ID 조합에 유일 제약을 둡니다.
- 요청 본문의 정규화 해시를 보존합니다. 같은 ID·다른 본문은 409로 거절합니다.
- 성공 결과와 업무 변경은 같은 트랜잭션에서 커밋합니다. 응답 유실 후 동일 ID로 재요청하면 원래 결과를 반환합니다.
- 같은 요청의 동시 실행은 유일 제약 충돌 후 원결과를 확인합니다. 타임아웃이면 재시도 가능 상태를 반환하며 새 작업을 만들지 않습니다.
- 인증·현재 데이터 접근 권한은 재조회 시에도 검사합니다. 캐시된 결과가 권한 검사를 우회하지 않습니다.
- 첫 버전에서는 요청 ID와 최소 결과 참조를 업무 이력 수명 동안 유지하는 안입니다. 만료 뒤 재실행되는 위험을 피합니다.
- 같은 출고 확정·원출고 중복 차감 등은 업무 유일 제약으로도 방지합니다. 다른 요청 ID를 만든 중복 클릭까지 고려합니다.

## 인증·조회 경계

Next.js의 화면 접근 검사만으로 보호를 끝내지 않고 API 명령·조회마다 사용자와 거래처 범위를 검증합니다.
공식 문서도 인증·인가를 서버 데이터 접근 경계에 모으고 Proxy에만 의존하지 않도록 설명합니다.
근거: [Next.js Authentication](https://nextjs.org/docs/app/guides/authentication), [Backend for Frontend](https://nextjs.org/docs/app/guides/backend-for-frontend).

거래처 ID는 인증된 소속에서 결정하며 클라이언트가 보낸 값으로 권한을 넓히지 않습니다.
계정 차단과 역할 회수의 적용 시점, 세션·CSRF·초대·MFA 방식은 인증 설계에서 확정합니다.
민감한 응답은 공용 캐시에 저장하지 않으며 로그에는 토큰·첨부 원문을 남기지 않습니다.

## 필수 실패 검증

1. 마지막 재고 7박스에 동시 주문 확정 30개: 예약 합계가 7 초과하지 않음.
2. 동일 출고 요청 10회: 출고·차감·정산 거래 각 1회.
3. 출고 커밋 직후 응답 끊김: 재요청으로 같은 출고 ID 반환.
4. 출고·잔량 취소 경합: 수량 보존, 이미 출고된 수량 취소 불가.
5. 반품 금액 확정·월 마감 경합: 차감 거래의 누락·이중 귀속 없음.
6. 입금 배분·환불·취소 경합: 원금 초과 사용 없음.
7. 트랜잭션 중간 오류: 일부 원장만 남지 않음.
8. 계정 차단 후 이전 요청 ID 재전송: 데이터 접근 거절.

동시 예약, 중복 출고, 출고·취소 경합, 반품·마감, 입금 배분·취소, 계정 차단과 실사 보류는 실제 PostgreSQL 통합 테스트에 포함됩니다. 주문 접수의 commit 후 응답 유실·API 인스턴스 교체·동일 결과 재생도 장애 주입으로 검증했습니다. 실제 배포 네트워크 장애와 실제 환불 경합은 아직 검증하지 않았습니다.
