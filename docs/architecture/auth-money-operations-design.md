# 인증·금액·운영 통합 설계안

최초 작성: 2026-09-05. 최종 갱신: 2026-09-09. 세션·MFA·정수 금액·세금·반올림·지급 기한, 운영 복원 기반과 배송·반품 첨부, ClamAV 저장 전 검사를 구현했습니다. 실제 배포 환경의 RPO/RTO와 ClamAV 네트워크 연결, 법정 증빙 연동은 아직 검증 전입니다.

## 인증과 계정

첫 버전은 이메일·비밀번호 로그인과 서버 저장 세션을 제안합니다. 공개 가입 없이 관리자가 계정을 초대합니다.
기존 프로젝트의 인증 계정·비밀값을 재사용하지 않습니다. 자체 인증과 외부 OIDC 모두 가능하지만,
이 초안은 외부 계정 서비스 의존을 줄이는 서버 세션 방식이며 검증된 인증 라이브러리 선택은 상세 구현 계획에서 확정합니다.
비밀번호 해시·토큰 생성·MFA 알고리즘을 직접 구현하지 않습니다.

- 브라우저에는 불투명 세션 ID만 HttpOnly 쿠키로 전달합니다. 운영에서는 Secure·SameSite=Lax·Path=/를 적용합니다.
- DB에는 세션 토큰의 해시와 사용자·만료·폐기 상태를 저장합니다. 로그인·권한 변경 시 세션을 교체하거나 폐기합니다.
- 유휴 2시간·최대 12시간을 제안합니다. API마다 세션·계정 활성·현재 역할을 검사합니다.
- 내부 운영·정산·시스템 관리자에게 MFA를 필수로 제안합니다. 복구 코드는 해시 보관·일회 사용하며 분실 시 계정 복구 절차를 기록합니다.
- 초대는 24시간·비밀번호 재설정은 30분 유효한 일회성 토큰으로 제안합니다. 재발행 시 이전 토큰을 폐기합니다.
- 로그인 실패는 계정/IP별 제한과 일시 지연을 적용합니다. 계정 존재 여부를 응답으로 드러내지 않습니다.
- 비밀번호 변경·계정 차단은 기존 세션을 폐기합니다. 역할 변경 후 이전 권한으로 작업할 수 없어야 합니다.
- 동일 출처의 웹·API 경로를 사용합니다. 쿠키 변경 요청에는 Origin 검사와 CSRF 토큰을 함께 검증합니다.
- 인증 토큰을 localStorage에 보관하지 않습니다. 로그·URL·내보내기에 토큰이나 비밀번호를 남기지 않습니다.

세션 쿠키 보호와 CSRF는 [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html),
[CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)을 근거로 검토했습니다.
유효기간과 MFA 적용 역할은 이 프로젝트에 대한 제안입니다.

## 금액과 단가

- 첫 버전은 KRW만 지원하고 고정 포장 단위의 정수 수량을 사용합니다.
- 거래 단가는 공급가액 기준 원 단위 정수로 입력하는 안입니다. 공급가액·세액·합계를 별도 표시합니다.
- 세금 구분·세율·반올림 정책은 상품/거래 조건에서 명시하고 주문 당시 값과 정책 버전을 보존합니다.
- 과세 구분과 실제 세율의 적정성은 운영 개시 전에 확인합니다. 미설정이면 주문 확정을 막고 임의 세율을 적용하지 않습니다.
- 내부 계산은 decimal 또는 정수 연산으로 수행합니다. DB 금액은 `numeric(18,0)`, 세율은 정확한 decimal 형식으로 제안합니다.
- API 금액은 문자열로 전달하고 JS Number의 부동소수 계산에 의존하지 않습니다.
- DB 제약과 입력 검증으로 음수 단가·허용 범위를 넘는 금액을 거절합니다. 반품 차감은 별도 거래 종류로 표현합니다.

PostgreSQL numeric은 정확한 수치 연산을 위한 타입입니다. 근거: [PostgreSQL Numeric Types](https://www.postgresql.org/docs/15/datatype-numeric.html).
문서의 타입 기능을 참고했으며 실제 인스턴스는 아래 확인한 16 계열이므로 최종 migration은 해당 버전에서 검증합니다.

### 부분 출고·반품의 원 단위 차이

정상 공급가액은 단가×수량입니다. 세액은 품목별 누적 출고 공급가액에 정책을 적용해 원 단위 반올림하고,
이번 출고 세액은 누적 목표 세액에서 이전 출고 세액 합계를 뺀 값으로 제안합니다.
분할 횟수 때문에 전체 금액이 달라지지 않게 합니다. 예시 세율은 계산 검수용 입력이며 법정 세율을 뜻하지 않습니다.

반품 세액은 해당 원출고 품목의 저장된 세액을 누적 인정 반품 수량 비율로 배분합니다.
이번 차감은 누적 목표 차감에서 이전 차감을 빼고, 전량 반품 때는 남은 원출고 금액 전부를 차감합니다.
이렇게 원출고보다 더 차감하거나 전량 반품 후 1원 잔액이 생기는 것을 막습니다.
할인·수수료·배송비 자동 계산은 첫 버전에서 제외하고 단가에 합의된 금액만 사용합니다.
이 계산 정책은 세무 증빙 생성과 별개이며 실제 운영 계약과 대조 후 확정합니다.

### 마감과 지급 기한

서울 시간 기준 월별 귀속과 관리자 마감은 확정 정책을 유지합니다.
지급 기한은 거래처별 `익월 N일`을 제안하며 기본값은 익월 10일입니다.
해당 월에 N일이 없으면 말일로 정하고 휴일 자동 이동은 하지 않는 안입니다.
확정 정산에 지급 기한을 보존하므로 거래처 설정 변경이 과거 정산을 바꾸지 않습니다.

## 확인한 Docker 환경

읽기 전용 `docker ps`로 다음을 확인했습니다.

- 컨테이너: `property-manager-postgres`
- 이미지: `postgres:16-alpine`
- 호스트 포트: `5432` (표시된 바인딩은 IPv4/IPv6 전체 인터페이스)

이후 실제 서버 버전 16.15와 DB 이름·전용 역할·권한을 확인하고 `b2b_stm`, `b2b_stm_test`를 구성했습니다. 기존 컨테이너와 부동산 DB 설정은 변경하지 않았습니다. 전체 인터페이스 바인딩만으로 외부 접근 가능 여부를 단정하지 않습니다.

DB 이름은 `b2b_stm`, 테스트는 `b2b_stm_test`로 구성했습니다. 생성 전 이름 충돌을 확인했습니다.
앱 계정·migration 계정을 분리하고 앱에는 DDL 권한을 주지 않았습니다. 테스트 계정은 업무 DB에 접속하지 못하게 검증했습니다.
DB 계정 분리가 자동으로 권한 격리를 보장하지 않으므로 기존 PUBLIC 권한까지 확인하되 기존 DB 권한은 임의 변경하지 않습니다.

## 실행·배포·백업

- 개발은 기존 PostgreSQL에 새 DB만 추가합니다. 웹·API의 로컬 포트는 충돌 확인 후 별도로 정합니다.
- 운영 웹/API는 HTTPS 역방향 프록시 뒤에 배치하고 `/api`는 NestJS로 전달하는 구성을 제안합니다.
- 로컬 Docker 재사용 결정은 공개 서비스의 호스트·도메인·네트워크 구성 확정과 구분합니다. 실제 운영 장소와 비용은 아직 정하지 않았습니다.
- 재고·정산 변경은 API에서 동기 확정하고 메일·내보내기 등은 DB 작업 큐와 outbox로 재처리합니다. Redis는 첫 버전 필수 의존성으로 두지 않는 안입니다.
- 작업은 처리 기한·소유권을 기록하고 실행기 재시작 시 회수합니다. 같은 결과 파일·알림 이벤트를 재사용해 중복을 줄입니다.
- DB별 일일 논리 백업과 운영 전 복원 리허설을 수행합니다. RPO 15분은 별도의 WAL 보관·기본 백업이 필요하며 DB별 dump만으로 달성했다고 주장하지 않습니다.
- WAL 시점 복구는 공유 인스턴스 전체를 별도 복구 환경에 복원한 뒤 B2B DB를 추출하는 안입니다. 원래 부동산 DB를 과거 시점으로 되돌리지 않습니다.
- 공유 인스턴스의 WAL·재시작 설정 변경은 기존 서비스 영향 분석을 먼저 수행합니다. 복구 검증용 임시 환경은 상시 DB 인스턴스를 새로 운영하는 것과 구분합니다.

기본 백업과 WAL을 조합하는 복원 방식은 [PostgreSQL 16 Continuous Archiving](https://www.postgresql.org/docs/16/continuous-archiving.html)을 참고했습니다.

## 첨부와 운영 점검

- 첫 버전 증빙은 JPEG·PNG·PDF, 파일당 10MB·업무 건당 5개로 구현했습니다. 서버에서 확장자·콘텐츠 유형·크기와 magic signature를 검증합니다.
- 소규모 첫 운영 범위에서는 PostgreSQL 비공개 `bytea`로 원문과 업무 연결을 원자적으로 보관하고, 매 목록·다운로드에서 역할과 거래처 소유권을 검사합니다.
- ClamAV `clamd`의 `INSTREAM` 검사에서 정상 판정을 받은 파일만 저장·제공합니다. 악성 판정은 거절하고 검사 장애는 fail-closed로 처리하며, 실제 배포 네트워크와 서명 갱신 운영은 배포 환경 선택 시 확정합니다.
- 로그에는 요청 ID·사용자 ID·업무 ID·오류 분류를 남기고 비밀값·첨부 본문은 제외합니다.
- 운영 전 DB 백업 실패, API 오류, 작업 큐 지연, 디스크 부족을 탐지하고 알림 담당자를 지정합니다.
- 운영 런북에는 재시작, 이전 앱 버전 복귀, migration 실패, 복원, 계정 복구 절차를 포함합니다.

## 승인과 남은 항목

이 문서의 인증 방식·금액 규칙·운영 방안을 묶어 검토합니다. 실제 인프라 지출·메일 발송·DB 생성은 실행하지 않았습니다.
승인 후 라이브러리/버전·DB 스키마·작업별 수락 기준을 최종 설계와 구현 계획으로 통합합니다.
운영 호스트·도메인·메일 서비스·파일 저장소 비용과 실제 세금 설정은 사용 환경 정보가 필요한 별도 항목입니다.
