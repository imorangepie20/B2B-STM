# SDTPL_ADM 테마 이식 설계

## 목적

`SDTPL_ADM`의 밝은 shadcn 대시보드 경험을 B2B 주문·재고·출고·정산 시스템의 모든 웹 화면에 적용한다. 사용자는 참조 테마를 직접 만든 것으로 확인했으며, 필요한 코드와 자산을 B2B 프로젝트로 복사해 사용할 수 있다.

## 현재 문제와 원인

현재 B2B 웹 앱은 페이지별 CSS로 화면을 만들었다. 일부 화면은 `Arial`과 `Georgia`를 직접 지정하고, 공통 페이지 셸·메뉴·카드·테이블 체계가 없다. 따라서 참조 테마와 비슷한 밝은 색상만 보일 뿐, 정보 구조와 조작 경험의 품질이 다르다.

## 선택한 방식

`SDTPL_ADM`에서 검증된 Tailwind 4, shadcn 토큰, 사이드바·헤더·브레드크럼·기본 컴포넌트를 B2B 웹 앱으로 이식한다. 참조 프로젝트의 예제 화면, 더미 데이터, 대시보드·AI·앱 기능은 가져오지 않는다. B2B 업무 데이터와 인증 API를 사용하는 화면만 새 셸 위에 다시 구성한다.

전체 참조 프로젝트를 제품 소스로 쓰지 않고, 복사한 파일은 `apps/web` 안에서 B2B 요구에 맞게 유지한다. 이후의 변경도 B2B 프로젝트에서만 수행한다.

## 디자인 기준

- light mode만 제공한다. 다크 모드 전환 UI는 이식하지 않는다.
- `Pretendard Variable`을 기본 한글 글꼴로 유지한다.
- 관리자: 접히는 좌측 사이드바, 고정 상단 헤더, 브레드크럼, 넓은 작업 영역, 카드·표·상태 배지·다이얼로그를 사용한다.
- 거래처: 주문·반품·정산에 집중한 간결한 상단 헤더와 카드형 모바일 레이아웃을 사용한다.
- 창고: 큰 터치 영역, 바코드 검색, 대기 작업 목록을 우선한다.
- 업무 상태와 위험 동작은 배지·경고·확인 다이얼로그로 구분하며 색상만으로 구분하지 않는다.

## 이식 범위

### 공통 기반

- Tailwind 4와 shadcn 토큰을 `apps/web`에 설정한다.
- 필요한 최소 의존성(`@base-ui/react`, `class-variance-authority`, `clsx`, `lucide-react`, `tailwind-merge`, `tw-animate-css`)만 추가한다.
- `SDTPL_ADM/src/components/ui`에서 실제로 사용하는 `button`, `card`, `sidebar`, `separator`, `tooltip`, `sheet`, `skeleton`, `badge`, `input`, `select`, `textarea`, `dialog`와 공통 유틸리티를 복사한다.
- 원본의 `AppSidebar`, `AppHeader`, `Breadcrumbs`를 B2B 메뉴·역할·경로에 맞게 복사·수정한다.

### 인증과 공통 화면

- `/` 로그인과 MFA 등록·확인·복구 흐름을 참조 테마의 인증 레이아웃과 폼·상태 컴포넌트로 전면 교체한다.
- 오류, 비어 있음, 로딩, 권한 부족 상태를 공통 카드·알림·스켈레톤으로 통일한다.

### 관리자 화면

- `/admin`을 업무 현황 대시보드로 재구성한다.
- 주문, 재고 정정, 단가, 반품, 정산, 입금, 계정 보안 화면을 공통 관리자 셸 안에서 동작하게 바꾼다.
- 기존 API endpoint, 폼 데이터, 권한 처리, 요청 중복 방지는 바꾸지 않는다.

### 거래처·창고 화면

- `/portal/orders`, `/portal/returns`, `/portal/settlements`와 `/warehouse/shipments`, `/warehouse/returns`에 공통 토큰·버튼·폼·상태 컴포넌트를 적용한다.
- 휴대폰 너비에서 작업 흐름과 제출 버튼이 항상 보이도록 검증한다.

## 단계와 완료 기준

1. 공통 기반: 새 토큰과 컴포넌트가 빌드되고, 기존 인증 화면이 깨지지 않는다.
2. 인증 전면 교체: 로그인과 MFA 등록·확인·복구 화면이 참조 테마의 인증 경험을 사용한다.
3. 관리자 기준 화면: `/admin`과 `/admin/orders`가 참조 테마와 같은 사이드바·헤더·카드 구조를 사용한다.
4. 관리자 확장: 나머지 관리자 업무 화면이 같은 셸과 컴포넌트를 사용한다.
5. 거래처·창고 확장: 주문·출고·반품·정산 화면의 디자인 체계를 통일한다.
6. 검증: API 빌드, 웹 빌드, foundation 테스트, 기존 업무 E2E, 인증·관리자·거래처·창고 1280px 및 390px Playwright 캡처를 모두 통과한다.

## 제외 범위

- 참조 테마의 AI, 채팅, 캘린더, 메일, POS, 예제·문서 화면
- 다크 모드, 테마 전환, 참조 프로젝트의 더미 데이터와 API
- 주문·재고·출고·정산 도메인 동작 변경

## 위험 관리

- 참조 프로젝트의 전체 49개 UI 컴포넌트를 복사하지 않고, 실제 B2B 화면에서 쓰는 최소 파일만 이식한다.
- API 요청과 권한 경계는 기존 화면의 테스트로 보존한다.
- 원본 `SDTPL_ADM/`은 읽기 전용으로 유지하고, 복사본과 수정본은 `apps/web`에만 둔다.
