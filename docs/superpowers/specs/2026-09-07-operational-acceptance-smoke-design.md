# 운영 인수 스모크 점검 설계

작성일: 2026-09-07

## 목적

현재 개발 DB와 실행 중인 API를 대상으로 역할별 접근 통제와 일상 조회 성능을 반복 검증한다. 운영 기준의 전체 부하 시험을 대체하지 않으며, 개발 중 회귀를 빠르게 찾는 인수 전 점검으로 사용한다.

## 점검 범위

- 비로그인 사용자의 보호 API 접근은 `401`이어야 한다.
- 거래처, 창고, 운영 역할은 자신의 조회 API에 접근할 수 있어야 한다.
- 거래처와 창고 계정은 관리자 API에 접근할 수 없어야 한다.
- 운영 계정은 MFA 확인 전 관리자 API에 접근할 수 없어야 한다.
- MFA 확인을 마친 운영 계정은 관리자 API에 접근할 수 있어야 한다.
- 거래처, 창고, 관리자 대표 조회 API를 30개 작업자로 동시에 호출한다.
- 전체 읽기 요청의 p95는 1,000ms 이하이고 예상하지 못한 상태 코드 비율은 0.1% 이하여야 한다.

## 데이터 보호

기존 데모 사용자를 조회하되 검증 전용 세션만 추가한다. 세션 토큰은 난수로 만들고 DB에는 SHA-256 hash만 저장한다. 점검 성공 여부와 관계없이 해당 세션을 삭제하며 주문, 재고, 출고, 정산 데이터는 변경하지 않는다.

## 결과 형식과 한계

명령은 역할별 권한 결과, 전체 및 endpoint별 요청 수·p50·p95·최대 응답 시간·오류율을 JSON으로 출력한다. 기본 실행은 30개 작업자와 300개 요청의 짧은 로컬 스모크다. 목표 규모인 거래처 100개, SKU 1,000개, 주문 100,000건, 주문행 1,000,000건과 30분 지속 부하는 별도 본 시험에서 검증한다.
