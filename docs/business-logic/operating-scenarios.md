# 업무 시나리오 초안

최종 갱신: 2026-09-09. 대상 업종과 주문·재고·출고·배송·반품·정산 정책은 확정됐고 피킹·검수, 배송·인도, 실사 보류, 불량품 해결과 실제 환불까지 구현했습니다. 수치는 설계용 예시이며 실제 업체 인터뷰 결과가 아닙니다.

## 기본 흐름 제안

1. 관리자가 거래처·상품·고정 포장 단위·거래처 단가를 등록합니다.
2. 공급처 입고를 기록하고 판매 가능 재고를 반영합니다.
3. 거래처가 주문합니다. 주문 당시 단가와 포장 정보를 보존합니다.
4. 관리자가 주문을 확인·확정하고 확보 수량과 대기 수량을 구분합니다.
5. 창고가 피킹·검수 후 실제 출고를 확정합니다.
6. 확정 출고 기준으로 정산하고 실제 입금을 배분해 미수를 계산합니다.

예약 시점은 관리자 확정 시점으로 승인됐습니다.
상세 비교와 예외 처리는 [주문·재고 확보 정책](order-and-allocation-policy.md)을 참고합니다.

## 부분 출고와 잔량

컵 10박스 주문에 가용 재고가 7박스이면 7박스 선출고·3박스 대기를 제안합니다.
대기 수량은 추가 입고 후 출고하거나 거래처 요청에 따라 취소합니다.
피킹 중인 잔량 취소는 창고 작업 해제와 일치시켜 이중 출고를 방지해야 합니다.

## 반품과 정산

확정 정책은 [반품·정산 정책](returns-and-settlement-policy.md)을 참고합니다.

반품은 원래 출고 내역에 연결해 요청 → 승인 → 실물 입고·검수 → 재고·금액 반영으로 처리하는 안입니다.
정상품은 판매 가능 재고로 복귀하고 불량품은 분리합니다. 승인만으로 판매 가능 재고를 늘리지 않습니다.

예시: 10박스 주문 → 7박스 출고 → 잔량 3박스 취소 → 출고분 1박스 반품 승인·검수 및 전액 차감 완료이면
최종 청구 대상은 6박스입니다. 별도 비용·할인 없는 예시입니다.
마감 이후 반품은 이전 마감을 덮어쓰지 않고 다음 정산에 조정 내역을 남기는 방안을 제안합니다.

## 예외 검증 시나리오

| 상황 | 요구하는 결과 또는 결정 과제 |
|---|---|
| 여러 거래처의 동시 주문 | 같은 가용 재고를 중복 확보하지 않음 |
| 모바일 출고 버튼 재입력·통신 재시도 | 출고와 재고 차감이 한 번만 반영됨 |
| 확정 후 응답 유실 | 재시도·조회로 기존 결과를 확인함 |
| 두 담당자의 같은 작업 변경 | 충돌을 감지하고 최신 상태를 기준으로 처리함 |
| 담당자의 교대·작업 반납 | 담당자 본인이 사유를 기록해 반납한 뒤 다음 담당자가 선점함 |
| 실사 수량 부족 | 사유와 작업자를 기록하고 예약 초과 해결 정책 적용 |
| 반품 수량 초과 요청 | 실제 반품 가능한 출고 잔량 초과를 차단함 |
| 입금 중복 등록·오배분 | 중복 방지 및 감사 가능한 정정 정책 필요 |
| 다른 거래처 정보 요청 | 서버가 조회·변경을 차단함 |

## 다음에 확정할 정책

1. 관리자 확인 후 주문 확정 방식은 확정했습니다.
2. 확정 시 예약, 부족 수량 대기, 주문 시 부분 출고 선택 정책을 확정했습니다.
3. 주문 최소 수량·포장 단위, 가격 적용과 변경 규칙.
4. 출고 확정 시점과 배송·인도 확인 범위.
5. 반품 허용 기준·비용·차감 시점과 불량품 처리.
6. 월 마감·입금 기한·세금·반올림·마감 후 조정 방식.
7. 예상 사용자·상품·주문량과 운영 복구 목표.
