# 주문 승인·재고 확보·출고 정책

작성일: 2026-09-05. 최종 갱신: 2026-09-09. 주문 처리 정책은 확정됐고 접수·확정·예약·재배정·부분 출고·취소 요청과 창고 담당 경쟁까지 구현했습니다. 주문별 부분 출고 선택값과 피킹·검수 단계는 남아 있습니다.

## 처리 방식 비교

| 방식 | 장점 | 부담 |
|---|---|---|
| 관리자 확인 후 확정 | 단가·수량·공급 일정의 예외를 출고 전에 확인 | 확인 대기와 담당자 업무 필요 |
| 주문 즉시 자동 확정 | 반복 주문 처리 속도가 빠름 | 단가·재고·거래 조건 예외를 자동 판정해야 함 |
| 조건부 자동 확정 | 정상 주문 자동 처리와 예외 확인 병행 | 초기 정책과 검증 조합이 늘어남 |

첫 운영 버전은 관리자 확인 후 확정을 제안합니다. 단순한 기준을 먼저 검증하고 이후 조건부 자동 확정을 검토합니다.

## 확정 정책

1. 장바구니와 접수 단계에서는 재고를 예약하지 않습니다. 접수는 공급 확약과 구분해 표시합니다.
2. 관리자가 확정할 때 최신 가용 재고를 확인하고 실제 확보 가능한 수량만 예약합니다.
3. 거래처는 주문 시 `부분 출고 허용` 또는 `전체 수량 확보 후 출고`를 선택합니다. 초기 기본값은 부분 출고 허용으로 제안하며 제출 전에 명시합니다.
4. 부분 출고 허용 주문은 확보 수량을 먼저 출고하고 부족 수량을 대기로 남깁니다.
5. 전체 확보 후 출고 주문도 가용분을 예약할 수 있지만 미취소 잔량 전체가 확보되기 전에는 출고 작업을 시작하지 않습니다. 장기 예약은 관리자 대기 목록에 노출하고 자동 취소하지 않습니다.
6. 추가 입고 후 대기 주문 배정은 관리자가 수행합니다. 기본 정렬은 주문 확정 시각 순이며, 순서를 바꾸면 사유를 남깁니다. 새 주문 확정 시 기존 대기 주문을 함께 보여줍니다.
   현재 구현은 관리자가 주문 상세에서 한 주문씩 최신 가용 재고를 재배정하며, 주문 목록은 접수·확정 시각 순으로 제공합니다. 임의 우선순위 변경 기능은 아직 제공하지 않습니다.
7. 출고 전 취소 요청이 접수되면 해당 잔량의 새 출고 작업을 보류합니다. 피킹 중인 작업은 담당자가 해제하고 취소를 확정한 뒤 예약을 해제합니다.
8. 출고 확정과 취소 요청이 경합하면 서버에서 먼저 확정된 결과를 기준으로 합니다. 이미 출고된 수량은 취소할 수 없고 반품 흐름을 사용합니다.
   확정 취소는 사유·처리자·처리 시각을 별도 감사 행에 영구 저장하고 관리자와 거래처 이력에서 조회합니다.
   현재 구현은 거래처 요청을 `submitted`로 저장한 동안 새 출고, 추가 배정과 직접 관리자 취소를 차단합니다. 관리자가 승인하면 남은 활성 예약만 해제하고, 반려하면 사유를 남긴 뒤 출고 보류를 해제합니다. 요청·검토의 실행자와 시각은 별도 감사 이력으로 보존합니다.
   현재 주문별 창고 담당 시작·반납 상태는 구현했습니다. 취소 검토 요청이 들어오면 담당을 자동 반납하고 새 출고를 차단합니다. 피킹 수량과 검수 완료 상태는 아직 별도 기록하지 않습니다. 먼저 확정된 출고를 되돌려야 하면 반품 흐름을 사용합니다.
9. 거래처가 제출한 주문의 품목·단가·수량을 관리자가 조용히 변경하지 않습니다. 초기 버전은 변경이 필요한 미출고 주문을 취소·재주문하며 원래 주문을 참조합니다. 부분 출고 이후는 잔량 취소와 추가 주문으로 처리합니다.
10. 피킹은 예약 재고 내에서 수행하고 출고 확정 시 실제 출고 수량만 물리 재고에서 차감합니다. 피킹만으로 정산 대상이 되지 않습니다.

## 재고 정의

- 정상 보유 재고: 창고에 있는 판매 적합 재고. 예약분을 포함합니다.
- 예약 재고: 특정 주문에 확보된 정상 재고. 피킹 중 수량도 포함하며 중복 차감하지 않습니다.
- 가용 재고: 정상 보유 재고 - 예약 재고.
- 검수 대기·불량 재고: 정상 보유 재고와 분리하고 가용 수량에 포함하지 않습니다.

출고 시 정상 보유 재고와 해당 예약을 같은 수량만큼 함께 줄입니다.
재고 정정으로 예약 초과가 예상되면 관련 SKU의 새 배정·출고를 보류하고 관리자가 예약 해제·대기 전환과 실사 정정을 함께 확정합니다.
부족 실사 결과는 예외 기록으로 즉시 보존하고, 해결 전에는 기존 숫자를 정상 가용 재고처럼 제공하지 않습니다.

## 수량 예시와 검수 기준

정상 보유 7박스에서 A 주문 10박스를 부분 출고 허용으로 확정하면 예약 7, 대기 3, 가용 0입니다.
B 주문이 동시에 접수돼도 같은 7박스를 다시 예약하지 않습니다. 동시 확정 시 서버에서 재고를 먼저 확보한 요청만 해당 수량을 예약합니다.
A가 7박스 출고되면 정상 보유 0, 예약 0, 미출고 잔량 3입니다. 추가 입고 5박스 중 A에 3박스를 배정하면 가용은 2박스입니다.

- 주문 수량 = 취소 수량 + 누적 출고 수량 + 미출고 잔량.
- 미출고 잔량 = 예약 수량 + 미확보 대기 수량.
- 반품은 누적 출고 이력을 줄이거나 주문 잔량을 자동으로 다시 열지 않습니다. 교환용 출고는 별도 정책이 필요합니다.
- 동일 출고 요청을 재전송해도 출고와 재고 차감이 한 번만 발생해야 합니다.
- 취소 요청·출고 경합은 실제 DB 통합 테스트로 검증했습니다. 실사 부족 상황은 계속 통합 검증 대상입니다.

위 수치는 설계 예시이며 자동 테스트 결과가 아닙니다.

## 남은 구현 결정

주문별 `부분 출고 허용` 선택값의 저장·집행과 재주문 가격 변경 안내는 후속 구현에서 확정합니다. 피킹·검수와 출고별 배송·인도 기록은 구현했습니다.
