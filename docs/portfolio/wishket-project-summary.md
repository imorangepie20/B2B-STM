# 중소 유통업체 B2B 주문·재고·출고·정산 시스템

## 프로젝트 목표

전화·메신저·스프레드시트로 분리된 거래처 주문과 창고 출고, 반품, 월 정산 업무를 하나의 데이터 흐름으로 연결했습니다. 주문을 받는 화면만 구현하는 대신 부분 출고, 재고 부족, 잔량 취소, 반품 검수, 마감 후 차감, 입금 오배분 정정처럼 실제 운영에서 생기는 예외를 끝까지 처리하는 것을 목표로 했습니다.

## 대상 사용자와 업무

| 사용자 | 주요 업무 |
|---|---|
| 거래처 | 계약 단가 상품 주문, 진행·잔량 확인, 미출고 취소 요청, 원출고 기반 반품 요청, 정산·입금 조회 |
| 창고 담당자 | 예약 재고 확인, 부분 출고, 반품 실물 검수, 정상·불량 수량 분리 |
| 관리자 | 기준정보·거래처 단가, 주문 확정·재배정, 입고·재고 정정, 반품 차감, 월 마감, 입금 배분, 계정·감사 운영 |

## 핵심 구현

- 관리자 확정 시점에 PostgreSQL 행 잠금으로 최신 가용 재고를 다시 확인하고 예약합니다.
- 부족 수량은 대기로 유지하고 추가 입고 후 다시 배정하거나 거래처 요청을 검토해 잔량만 취소합니다.
- 출고는 예약 잔량 범위에서 여러 번 나눠 확정하며 재고 차감과 매출 원장을 같은 transaction으로 기록합니다.
- 반품은 실제 `shipment_lines`를 기준으로 요청하고 검수된 정상 수량만 판매 가능 재고로 복귀시킵니다.
- 월 정산은 출고·반품 차감 원장을 고정하며 마감 이후 반품은 다음 기간 조정으로 남깁니다.
- 입금 등록, 정산 배분, 취소와 재배분을 원기록 삭제 없이 역처리 이력으로 보존합니다.
- 상태 변경 명령은 `requestId` 결과를 보존해 통신 재시도와 중복 클릭이 업무를 이중 반영하지 않게 합니다.
- 거래처 소속, 역할, MFA, CSRF를 서버 API 경계에서 검사하고 주요 변경은 작업자·대상·사유와 함께 조회합니다.

## 기술 구성

- Frontend: Next.js 16.3.4, React 19, TypeScript, Tailwind CSS, shadcn/ui, Recharts 3.8.0
- API: NestJS, TypeScript
- Database: PostgreSQL 16, 업무·테스트 DB와 역할 분리
- Verification: Node test runner, 실제 PostgreSQL 통합 테스트, Playwright, 운영 정합성·권한·동시 조회 스모크
- Design: `SDTPL_ADM` 라이트 테마, Geist Sans, 데스크톱·모바일 반응형 화면

관리자, 창고, 거래처 화면의 통계는 용도에 따라 면적, 막대, 누적 막대, 복합, 가로 순위 그래프로 구성했습니다. 화면에 내려온 일부 목록을 다시 세지 않고 PostgreSQL에서 권한 범위 전체를 집계합니다.

[대화형 시스템 아키텍처](b2b-stm-architecture.html)는 역할별 웹, API 업무 경계, 인증, 핵심 업무 모듈과 원장 DB의 관계를 보여줍니다.

## 구현에서 중요하게 판단한 점

1. 웹 화면에서 수량과 금액 규칙을 계산하지 않고 NestJS API와 PostgreSQL transaction을 단일 기준으로 사용했습니다.
2. 주문 상태 하나에 물류·반품·정산 진행을 섞지 않고 예약, 출고, 검수, 차감, 마감, 배분 기록을 분리했습니다.
3. 원장을 수정·삭제해 과거를 맞추지 않고 취소·역처리·다음 기간 조정으로 변경 근거를 보존했습니다.
4. 목록 데이터가 증가해도 현재 페이지에서만 검색하는 오류가 없도록 주요 주문·창고·재고·반품 화면에 서버 검색과 페이지 처리를 적용했습니다.

## 현재 공개하는 한계

- 단일 유통사·단일 창고 운영 모델입니다.
- 택배, 은행, 회계, 전자세금계산서 자동 연동은 범위 밖입니다.
- 현재 성능 증거는 개발 DB에서 동시 작업자 30명·조회 300건을 실행한 로컬 스모크입니다.
- 주문 100,000건·주문행 1,000,000건·30분 지속 부하 본 시험은 사용자의 요청으로 중단했으며 달성했다고 표시하지 않습니다.
